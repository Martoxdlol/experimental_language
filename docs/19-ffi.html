The three concerns

Each concern has its own opt-in syntax — no global unsafe block.

1. Two heaps recap

Managed vs foreign Managed heap: tracing GC (MMTk · Immix). Holds normal structs, lists, maps, strings, closures. Foreign heap: opaque to the GC; manual lifetime. *T is a raw pointer into either region; the GC inspects the address range at runtime to decide whether to trace. See 16-memory.

2. Pointers

Three pointer surfaces. & is the only implicit pin in the language.
extern function getrusage(who: i32, out: *Rusage): i32

function snapshot(): Rusage | i32 {
  var ru = Rusage { ru_utime: Timeval { ... }, ru_stime: Timeval { ... } }
  var rc = getrusage(0i32, &ru)        // & auto-pins ru for the call
  if rc != 0i32 { return rc }
  ru
}

3. Extern structs & layout decorators

extern struct Buffer { pub data: *u8, pub size: u64 }
extern struct Timeval { pub tv_sec: i64, pub tv_usec: i64 }

Consequences: no object header; can't be a generic argument to managed collections; all field types must be extern-compatible; may live on the foreign heap, on the stack, or as a by-value parameter/return.

Layout decorators

Four compiler-blessed proc-macros, registered like @Derive. Placement: above the item, before pub.
ReprC auto-impl Auto-implemented for every extern struct, every numeric primitive, every pointer type, and every @Transparent wrapper. It's the constraint used by generic FFI helpers like Foreign.alloc<T: ReprC>().

Scope of [T; N] is narrow Fixed-size arrays are allowed only as extern struct field types and as extern function parameter/return types (typically via *[T; N]). No general-purpose arrays in non-extern code.

5. Foreign allocation — Foreign

pub struct Foreign;

extend Foreign {
  function alloc<T: ReprC>():                                  *T | null
  function alloc_zeroed<T: ReprC>():                           *T | null
  function alloc_flex<T: ReprC, E: ReprC>(extra_count: usize): *T | null
  function realloc<T: ReprC>(p: *T, new_size: usize):          *T | null
  function free<T: ReprC>(p: *T)
}
Foreign allocation is fallible Returns null on OOM — unlike managed allocation, which panics (see 16-memory §9).

Flexible array members

extern struct Message {
  pub kind:   u32,
  pub length: u32,
  pub data:   *u8,
}

function make_message(kind: u32, payload: Buffer): *Message | null {
  var p = Foreign.alloc_flex<Message, u8>(payload.size as usize)
  if p is null { return null }
  ...
  p
}

6. Strings — CStr / CString / Buffer

str is not ABI-compatible with C strings (managed-heap UTF-8 with a length header, not NUL-terminated). core:ffi ships boundary types.

Auto-materialized stack temporaries When the compiler sees an extern call site like extern_fn(my_str) where the foreign signature expects *const c_char and my_str is a managed str, it materializes a NUL-terminated copy in a stack buffer (or in the nonmoving space for large strings) for the duration of the call. No pin, no foreign alloc, no GC interaction — the common case is zero-overhead. Falls back to CString.from_str only when the copy must outlive the call.

CStr — borrowed

extern struct CStr {
  pub ptr: *u8,
}

NUL-terminated UTF-8 view. Caller keeps the buffer alive. from_ptr, byte_len, to_str.

CString — owned

pub struct CString { ... }

from_str(s) → foreign-heap copy with NUL. Implements Drop — frees on scope exit.

Buffer — ptr + size

extern struct Buffer {
  pub data: *u8,
  pub size: u64,
}

Length matters separately from NUL. See 18-stdlib §8.

7. Extern functions & decorators

// Import (no body)
extern function malloc(size: c_size_t): *c_void | null

// Export (with body) — emitted with C calling convention
extern function on_tick(d: *MyStruct) {
  (*d).counter = (*d).counter + 1
}
Exported externs are top-level and cannot capture A C function pointer has no environment slot. For state, take a *c_void (or *T) user-data parameter — the conventional C callback pattern.

8. Function pointers and callbacks

extern (T1, T2, ...) => R is the function-pointer type form (see 09-functions §3). Closures cannot cross the C ABI — only top-level extern function symbols are callable as extern (...) => R values.

extern struct Callback<C, R> {
  pub fn:   extern (*c_void, C) => R,
  pub data: *c_void,
}

10. Pinning

The GC may relocate managed objects during collection (Immix evacuates fragmented blocks). A *T pointing into the managed heap is only safe across an extern call if the object is pinned — meaning the collector won't move it for the pin's lifetime. Pinning does not prevent reclamation: an unreachable pinned object is still collected, just not relocated first. See 16-memory §14.

Pin counts compose by object (nesting works); the runtime keeps a small per-object pin counter independent of the GC.

@Pinnable — pre-commit to the nonmoving space

For types pinned often, decorate the definition:

@Pinnable
pub struct AudioRingBuffer {
  ... fields ...
}

Instances are allocated in the nonmoving space — no per-pin runtime cost, no heap fragmentation. Use this for types passed into long-running C libraries (DSP buffers, GPU upload regions, ring buffers shared with kernel drivers).

Don't long-pin objects in default Immix space A dynamic pin on an object in the default space blocks evacuation of its block. Across many collections this fragments the heap. Either mark the type @Pinnable, or — for references that don't need a raw pointer — use a handle (next section).

11. Handles — long-lived foreign rooting

When foreign code retains a managed reference across calls (callback registrations, observer patterns, foreign data structures storing managed objects), use a handle: an opaque cookie that roots the object without blocking movement. The collector follows the handle table; on evacuation, it rewrites the table slot — the cookie value never changes.

pub struct Handle<T>;     // release explicitly; Drop is async best-effort

extend<T> Handle {
  static function acquire(value: T): Handle<T>
  function raw(self): u64                          // opaque cookie for foreign storage
  function release(self)                           // explicit release; also runs on Drop

  static function resolve<T>(cookie: u64): T       // panics on stale cookie
}
Two answers to two different problems. Picking the right one keeps the heap movable and ergonomic.
// GUI listener registered with a C library
function install_listener(l: Listener) {
  var h = Handle.acquire(l)              // h: Handle<Listener>
  c_gui_register(on_native_event, h.raw())
  // ... h must outlive the registration; typically stored alongside the registration
}

// Foreign callback (exported extern)
@Reentrant("any")
extern function on_native_event(cookie: u64) {
  var listener = Handle.resolve<Listener>(cookie)
  listener.notify()
}
Cookie stability A handle's raw() value is stable for the handle's entire lifetime — foreign code may store, compare, hash it freely. After release() the cookie is stale; using it via Handle.resolve panics. Stale cookies are not memory-unsafe; they are a program error.

12. Runtime semantics — safepoints & trampolines

Every extern boundary is a safepoint: the mutator's live managed pointers are recorded in a precise stack map (see 16-memory §6), the thread is marked "blocked-in-foreign," and the foreign call runs without holding back GC. On return, the thread re-acquires mutator state and re-reads any roots that may have moved while it was away.

Exported externs (managed code callable from foreign code) get an automatic entry trampoline: attach the thread if needed, push a frame the GC can stack-map, run the body, drop the trampoline frame on return. The trampoline is invisible at the source level — it's part of the calling convention.

Imports get a transparent safe-point wrapper; exports declare their threading and panic policy.

Foreign threads calling exports

// Manual attach/detach
import { attach_thread, detach_thread } from "core:ffi"

extern function on_tick(data: *c_void) {
  attach_thread()
  do_work(data)
  detach_thread()
}

// Or @Reentrant("any") — compiler emits attach/detach automatically
@Reentrant("any")
extern function on_tick(data: *c_void) {
  do_work(data)
}
Signal handlers Running language code from a POSIX signal handler is UB unless the handler is on a currently-attached thread and the body is @Reentrant("any") — and even then, the usual signal-safety rules (no allocation, no locks) apply. Practical advice: don't.

15. Restrictions on extern signatures

✓ Allowed

  • Numeric primitives, bool, char, isize, usize.
  • C-width aliases (c_int, …).
  • *T and *T | null (NPO).
  • extern struct by value.
  • @Union extern struct by value.
  • @Transparent wrappers.
  • [T; N], typically via *[T; N].
  • extern (...) => R function pointers.
  • extern type T via *T.
  • Generic T in pointer position only.

✗ Not allowed

  • Non-extern structs, str, List, Map, interface objects — by value.
  • Discriminated unions other than NPO-eligible null | P forms. Wrap in a pointer.
  • Closures (no environment slot). Use extern (...) => R or Callback<C, R>.

16. Summary

  • Layout — extern struct declares C layout. @Packed(N), @Align(N), @Transparent, @Union modify it.
  • Pointers — *T raw pointer. *T | null via NPO. &expr address-of (auto-pin). *ptr dereference. as for pointer reinterpretation.
  • Foreign types — extern type T opaque handles. [T; N] in extern positions only.
  • Globals — extern var name: T with optional @Link.
  • Allocation — Foreign.alloc family. Buffer, CStr, CString are the boundary types.
  • Functions — extern function for imports and exports. Six decorators: @Link, @Symbol, @CallConv, @Variadic, @Reentrant, @OnPanic.
  • Pinning — prevents movement. & auto-pin · with_pin scoped · Pin.acquire/PinHandle<T> long-lived · @Pinnable for pre-commit to nonmoving space.
  • Handles — Handle<T> for long-lived foreign-stored references; movement-friendly alternative to pinning; .release() explicitly.
  • Runtime — every extern boundary is a safepoint with precise stack maps; exports get entry trampolines; @Reentrant for foreign threads; @OnPanic for export panic policy.
  • Auto-materialization — str → *const c_char at call sites becomes a stack temporary, no foreign alloc.
  • Tooling — lang ffi bindgen/cbindgen/check/layout.
