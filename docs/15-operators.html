15. Operators & Operator Overloading

Most operators are sugar for method calls on built-in interfaces in core:prelude. Implement the interface; get the operator.

NOT overloadable &&, ||, ! on bool are built-in and cannot be overloaded — they short-circuit, which can't be expressed as method calls. ! on user types can be overloaded (via Not).

1. Arithmetic

pub interface Add<Rhs = Self, Output = Self> { function add(self, rhs: Rhs): Output }
pub interface Sub<Rhs = Self, Output = Self> { function sub(self, rhs: Rhs): Output }
pub interface Mul<Rhs = Self, Output = Self> { function mul(self, rhs: Rhs): Output }
pub interface Div<Rhs = Self, Output = Self> { function div(self, rhs: Rhs): Output }
pub interface Mod<Rhs = Self, Output = Self> { function mod(self, rhs: Rhs): Output }
pub interface Neg<Output = Self> { function neg(self): Output }

Primitives implement these for matching types. str implements Add<str, str> (concatenation).

extend Vec3: Add<f64, Vec3> {
  function add(self, k: f64): Vec3 {
    Vec3 { x: self.x + k, y: self.y + k, z: self.z + k }
  }
}

a + b resolves by matching the types of a and b to the most specific Add impl.

2. Logical

pub interface Not<Output = Self> { function not(self): Output }

// !mask on integers means bitwise NOT (Not impl on i32, i64, etc.)
extend i32: Not<i32> {
  function not(self): i32 { ... }
}
Bitwise NOT is !; ~ is an accepted synonym The canonical NOT operator is !. On integers it resolves to the Not impl (bitwise NOT); on bool it is logical NOT — the compiler picks based on the operand type. The lexer also recognises ~ for users coming from C / Rust; ~x on an integer is desugared to !x in the parser. Prefer ! in new code.

3. Bitwise

pub interface BitAnd<Rhs = Self, Output = Self> { function bitand(self, rhs: Rhs): Output }
pub interface BitOr<Rhs = Self, Output = Self>  { function bitor(self, rhs: Rhs): Output }
pub interface BitXor<Rhs = Self, Output = Self> { function bitxor(self, rhs: Rhs): Output }
pub interface Shl<Rhs = Self, Output = Self>    { function shl(self, rhs: Rhs): Output }
pub interface Shr<Rhs = Self, Output = Self>    { function shr(self, rhs: Rhs): Output }
Two key rules
  • Shift right on signed integers is arithmetic (sign-extending).
  • Shifting by >= width(T) panics in both debug and release.
  • | in type position constructs unions; in expression position it is BitOr. Context disambiguates.

4. Equality

pub interface Eq {
  function eq(self, other: Self): bool
  function ne(self, other: Self): bool { !self.eq(other) }
}

Primitives have built-in Eq. User types must implement it explicitly — there is no implicit field-by-field equality. Derive with @derive(Eq) (see 22-macros).

5. Ordering

pub type Ordering = Less | Equal | Greater
pub struct Less;
pub struct Equal;
pub struct Greater;

pub interface Ord: Eq {
  function cmp(self, other: Self): Ordering

  function lt(self, other: Self): bool { self.cmp(other) is Less }
  function le(self, other: Self): bool {
    var o = self.cmp(other)
    o is Less || o is Equal
  }
  function gt(self, other: Self): bool { self.cmp(other) is Greater }
  function ge(self, other: Self): bool {
    var o = self.cmp(other)
    o is Greater || o is Equal
  }
}

Numeric primitives and char implement Ord. str implements Ord (lexicographic by Unicode scalar values). bool and null do not.

6. Indexing

pub interface Index<Idx, Output> {
  function index(self, i: Idx): Output
}

pub interface IndexMut<Idx, Output>: Index<Idx, Output> {
  function index_mut(self, i: Idx, v: Output)
}

Out-of-bounds behavior is per-type. List<T> and Map<K, V> panic on [] for missing or out-of-range; use .get(i)/.get(k) for the T | null variant.

A type can implement multiple Index<Idx, Output> impls for different Idx types — e.g. a Matrix indexed by both i64 and (i64, i64).

7. Hashing

pub interface Hash {
  function hash(self): u64
}

Map<K, V> requires K: Eq + Hash. The contract: a.eq(b) implies a.hash() == b.hash().

Primitives implement Hash. str implements Hash. Tuples implement Hash if every component implements Hash.

8. Cloning

pub interface Clone {
  function clone(self): Self
}
Primitives clone trivially. Use @derive(Clone) for field-by-field deep copy.

9. Drop

pub interface Drop {
  function drop(self)
}

Called by the runtime just before reclaiming a managed object. Use to release foreign resources, log, etc.

When drop runs

  • Unreachable object, regular GC — asynchronously, from the finalizer queue, in unspecified order. See 16-memory §8.
  • Program exit — best-effort pass; may skip finalizers entirely.
Drop is asynchronous and not guaranteed drop runs eventually, on a finalizer thread, in unspecified order, only after the collector observes the object as unreachable. It may never run (at program exit, or if the object is leaked). A panicking Drop impl aborts the process. For any resource that needs deterministic release (files, locks, transactions, handles), call the release method explicitly — the language provides no scope-exit hook.
dynamic does not implement Drop The type dynamic itself has no impl. A value stored in a dynamic still runs its underlying Drop when the GC reclaims it — the box's type pointer points at the real type's descriptor. You just can't call .drop() through the dynamic binding without narrowing first. See 12-type-logic §5.

10. Stringification — ToStr

pub interface ToStr {
  function to_str(self): str
}
String interpolation desugars to ToStr-based concatenation.

Built-in implementations

  • Numeric primitives — decimal representation.
  • bool — "true"/"false".
  • char — single-character str.
  • str — identity.
  • null — "null".
  • List<T> — "[a, b, c]" (requires T: ToStr).
  • Map<K, V> — "{k1: v1, k2: v2}" (requires both implement ToStr).
  • Tuples — "(a, b, c)" (every component must implement ToStr).

Auto-derive

@Derive(ToStr)
pub struct Person { pub name: str, pub age: i32 }

// Person { name: "Alice", age: 30 } produces:
// "Person { name: Alice, age: 30 }"
No Display / Debug split Some languages distinguish user-facing from developer-facing stringification. This spec collapses them into one ToStr. Rationale: most string output is logs or UI (which goes through a localization layer anyway). One interface, smaller surface.

For numeric primitives, value as str is sugar for value.to_str() — keeping one stringification path through the type system.

dynamic does not implement ToStr Interpolating a dynamic binding ("$d") is a compile error. Narrow first — usually if d is ToStr { … } — and call to_str() in the branch. The same applies to Clone, Eq, Hash, and Ord: none of them dispatch through dynamic. See 12-type-logic §5.

11. ReprC — disabling object header for FFI

pub interface ReprC { }

Marker interface (no methods). Implementing ReprC asks the compiler to lay out the struct without the two-word object header — standard C struct layout, suitable for FFI.

Prefer extern struct A ReprC struct loses the ability to be referenced from managed code as a normal heap object — the GC cannot trace it. In practice, prefer extern struct (see 19-ffi). ReprC is for the rare case where a struct must be both managed-accessible and C-layout. Cross-tracing rules are unspecified; mark them only if you understand the implications.

12. Precedence summary

The canonical precedence table is in 07-expressions §5. Overload method calls do not see their own precedence — precedence is fixed at the operator level.

Non-associative comparisons == and != are non-associative. <, <=, >, >= are also non-associative. a < b < c is a parse error.

13. Operator overloading and dispatch

Operator method calls follow the same monomorphization / dyn-dispatch rules as any other method call (see 11-generics). Operators on generic-bounded types compile to direct calls; operators on interface-typed values use vtable dispatch.

14. No bespoke operator definitions

No new operators You can only overload the operators in §Map by implementing the corresponding interface. There is no way to define new operator symbols or override operator precedence per-type.
