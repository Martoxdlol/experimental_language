7. Expressions

The language is expression-oriented — most constructs produce a value. This chapter covers blocks, if, match, operators, calls, and the statement/expression split.

1. Block expressions

A block { ... } is a sequence of statements ending in an optional trailing expression. The block evaluates to the trailing expression, or to null if there is none.

The trailing ; is the difference between a value-producing block and a side-effecting one.

Blocks introduce a new lexical scope (see 06-variables §3).

Block vs trailing closure A { ... } immediately following a call f(...), an identifier callable, or ] is parsed as a trailing closure (sugar for passing it as the last argument — see 09-functions §6). Anywhere else a { ... } is a plain block expression.

2. if expression

if is an expression. Parens around the condition are not required and not conventional. Parens are only needed for the struct-literal ambiguity (see below).

var status = if age >= 18 { "Adult" } else { "Minor" }

var grade =
  if score >= 90 { "A" }
  else if score >= 80 { "B" }
  else if score >= 70 { "C" }
  else { "F" }

Type of the result

The type is the union of branch types (after normalization):

var v = if cond { 1 } else { "hi" }   // v: i64 | str

Statement form (no else)

Without else, the value is null and the type of both branches must unify:

if x > 0 {
  print("positive")
}
// Same as:
//   if x > 0 { print("positive") } else { null }
Condition must be bool No implicit truthiness for integers, strings, or pointers. if v is T { ... } is a special case for flow narrowing — see 12-type-logic.

Brace ambiguity in headers

Two different constructs use { ... } in expression position: struct literals (Range { current: 0, end: 5 }) and trailing closures (xs.map { it * 2 }). In the bare top-level expression of an if / while / for / match header, the parser can't tell where the header ends and the body begins — so both forms must be wrapped in parens.

Wrap the offending expression in parens. The rule covers both brace-using constructs uniformly.

3. match expression

The structured way to dispatch on a value. Most useful for unions. Arms are separated by commas.

match value {
  Pattern1 => expr1,
  Pattern2 => expr2,
  ...
  _        => default_expr,
}
or use _ · Primitives: _ arm required · Structs: { .. } covers all fields. Reachability — compile-time warning Arms try top-to-bottom. Unreachable arms (fully covered by earlier ones) emit a warning.
Top-to-bottom evaluation, exhaustiveness checked at compile time.
match n {
  i64 x if x > 0 => "positive",
  i64 x if x < 0 => "negative",
  i64 _          => "zero",
}
Binding modes Bindings in patterns are by-reference for reference-type fields (no clone), by-value for primitives. The bound name is a regular var — mutable inside the arm body.

Same . for member, tuple position, and static/namespace access. No separate ::.

Index

list[0]

Calls Index.index / IndexMut.index_mut. Out-of-bounds behavior is implementation-defined per type — List<T>/Map<K,V> panic; get/set return T | null.

7. Statements

Statements terminate with ;. The last expression in a block may omit ; to be the block's value.
