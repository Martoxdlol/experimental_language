1. Source encoding

Source files are UTF-8. Line breaks are \n or \r\n; they are equivalent.

2. Comments — four forms

Four forms. Two are ignored by the compiler; two are doc comments attached to items. The two doc forms differ in which item they attach to.

Two doc comments, two recipients. Both are first-class syntactic attributes.
// Line comment — to end of line.

/*
  Block comment.
  /* Block comments nest. */
*/

/// Documents the item that follows.
/// Markdown is the convention for body content.
pub struct Person {
  /// The person's name.
  pub name: str,
}

//! Documents the enclosing module.
//! Use this at the top of a file to document the module itself.
  • /// — outer doc, attaches to the next item. Multiple consecutive lines form one doc block.
  • //! — inner doc, attaches to the enclosing module. Top of file only.
  • Body is plain text; docgen interprets as Markdown.
  • Visible to procedural macros via ctx.docs(input) — see 22-macros.
  • A /// with no recipient (end of file, inside a function body) is a compile warning.

3. Identifiers

Identifiers start with a Unicode letter or _, followed by letters, digits, or _. Case-sensitive. ASCII recommended for portability. Reserved words (see §11) cannot be used as names.

4. Integer literals

Four bases plus optional digit grouping with _ and an optional type suffix. The pieces compose in a fixed order.

Composable parts: prefix + digits + optional suffix. Type resolution walks four rules in order.
42        // decimal       0xFF      // hex
0o17      // octal          0b1010    // binary

1_000_000        // grouping with _, ignored
0xFFFF_FFFF
0b1010_0101

42i8  42i16  42i32  42i64
42u8  42u16  42u32  42u64
42isize  42usize

5. Floating-point literals

3.14          // f64 by default
1e6
2.5e-3
1.0f32
1.0f64

A bare float literal is f64 unless context forces f32. Integer-shaped literals do not implicitly become floats — use a suffix or an annotation.

6. Booleans & null

true · false · null. Lowercase only. bool is a primitive (see 02-types); it is not a union of singletons. null is both the name of the empty type and its sole value.

7. Character literals & escapes

A char literal is a single Unicode scalar value in '…'. 32 bits wide; range 0..=0x10FFFF excluding the surrogate range.

Quote style is a hard split — 'x' is never a one-char string and "x" is never a char.

8. String literals & interpolation

String literals are UTF-8 and produce str values. str is immutable and heap-allocated (see 02-types and 18-stdlib).

Two interpolation shapes

Interpolation desugars to + chains of .to_str() calls.
var name = "Alice"
print("Hello, $name")                  // Hello, Alice

var user = User { name: "Alice", age: 30 }
print("Hello, ${user.name}, age ${user.age}")

print("Total: ${items.size() + 1}")
Stringification rule Interpolation desugars to "x = " + x.to_str(). Primitives, str, and null implement ToStr out of the box; user types implement it explicitly to participate.

Raw strings (opting out of escape/interpolation processing) are not in this version of the spec.

10. Statements & whitespace

  • Statements terminate with ;.
  • The last expression in a block may omit ; — the block then evaluates to that value (see 07-expressions).
  • A trailing ; discards the value; the block evaluates to null.
  • Whitespace separates tokens but is otherwise insignificant. Indentation has no semantic meaning.
  • -1 in expression context is unary minus on literal 1 — not a negative literal. Matters at pattern-syntax boundaries; e.g. i64.MIN must be written carefully when matched.

11. Keywords

All reserved identifiers. Self with a capital S is its own keyword.
Reserved for the future yield is reserved — the language does not currently support generator syntax (see 21-async).
Contextual keywords A small number of identifiers are reserved only in specific positions and otherwise parse as ordinary identifiers:
  • static — recognised before function inside interface and extend bodies (e.g. static function new(): Self). Equivalent to declaring the method with no self parameter; both forms are accepted.
  • from — recognised after the name list of a named import (import { a, b } from "lib").
  • it — implicit single parameter inside a trailing-closure body when the arity is 1 and no explicit parameter list is given. Inside any other context it is just an identifier.
None of these prevent you from using the same word as a variable name elsewhere.
