The three escape routes

No implicit sharing — every cross-thread transfer is one of these three.

1. Threads — std:thread

pub function Thread.spawn<R>(work: () => R): JoinHandle<R>
// Async overload: when `work` is an async closure `() => Future<R>`, the worker
// polls the future until it resolves and the handle joins on the awaited `R`:
pub function Thread.spawn<R>(work: () => Future<R>): JoinHandle<R>

pub struct JoinHandle<R> { ... }

extend<R> JoinHandle<R> {
  function join(self): Future<Joined<R> | Panicked>   // async — await it
  function detach(self): null
}

pub struct Joined<R> { pub value: R }
pub struct Panicked  { pub message: str }

Thread.spawn always returns a JoinHandle<R>. The handle itself is not a Future; call join() and await the returned future when you need the result.

Panicked is an ordinary result value: it implements Eq, Clone, Hash, ToStr, and std:fmt.Debug. Runtime handles such as JoinHandle remain handle types, not plain value records.

join is async and non-blocking. join() does not park the calling OS thread. It returns a Future<Joined<R> | Panicked> (see async) that you await inside an async body. Polling the future checks whether the worker has finished: if so, it resolves to Joined<R> { value } (or Panicked { message }); otherwise it registers the executor's waker and reports Pending so the task suspends while the joining thread is free to interleave other work. When the worker finishes, it invokes the stored wakers, which re-poll the awaiting task. 
function collect(h: JoinHandle<R>): Future<R> async {
  match await h.join() {                  // suspends until the worker finishes
    Joined<R> j => j.value,
    Panicked p  => panic("worker: " + p.message),
  }
}
Two ways to get an async worker Thread.spawn accepts either an ordinary non-async closure () => R or an async closure () => Future<R>, and always returns a JoinHandle<R>. With an async closure the worker polls the future until it resolves on its own OS thread, so the handle joins on the awaited R (not a Future<R>); such a worker may await and lock a Shared<T> (§4). The alternative is the spawn keyword from 21-async — spawn EXPR schedules a future on a worker and itself evaluates to a Future<T> you await. The two differ only in the handle they yield: Thread.spawn gives a JoinHandle<R> (with join/detach), the spawn keyword gives a bare Future<T>. Thread.spawn keeps its one-OS-thread per-worker guarantee; spawn EXPR runs on the shared work-stealing executor. Only an ordinary non-async Thread.spawn closure cannot await or lock (§4).
One OS thread per Thread.spawn worker — by design Thread.spawn is Otter Fusion's one-OS-thread-per-worker primitive: every worker gets its own OS thread, ordinary or async. That is intended, not a limitation — you reach for Thread.spawn precisely when CPU-bound or OS-thread-affine work must run outside the shared executor. It is not a public substitute for wait-capable target APIs: those must expose explicit async futures at the Otter Fusion surface. The trade-off is that Thread.spawn does not scale to thousands of mostly idle workers: each holds a thread even while suspended on an await. For massive, lightweight concurrency, use the spawn keyword (21-async §6), whose tasks share the executor.
Task.spawn on the work-stealing executor The std:task module provides Task.spawn: the same surface as Thread.spawn (the same closure forms, the same JoinHandle<R> with join/detach, and the same safety model — by-value capture snapshots for cross-task isolation plus Shared<T>/channels for shared state), but scheduled on an M:N work-stealing executor instead of a dedicated OS thread per worker. You write the same thread-like code; the runtime multiplexes many lightweight tasks onto a small thread pool, scaling to far more concurrency without one OS thread each. Creating the runtime's executor worker OS threads is a bracketed native-state boundary, separate from the user task's non-blocking scheduling contract; idle executor workers also publish runtime-native/no-root state while parked on the work queue, so they do not hold stop-the-world GC as running mutators. It complements Thread.spawn rather than replacing it: keep Thread.spawn for CPU-heavy or OS-thread-affine work that needs its own OS thread, reach for Task.spawn for high task counts. Task.spawn also returns a JoinHandle<R>, not a Future<R>; await handle.join() to observe Joined | Panicked | Cancelled. Ordinary stdlib operations such as the remaining in-memory std:io Reader/Writer/Seeker methods and buffered adapter reads/writes, child metadata/current-stdio accessors id()/stdin()/stdout()/stderr() are non-Future metadata/current-placeholder values too, with current child stdio returning null and future streamed child stdio reserved for async stream contracts. Any wait-capable target operation discovered at the public surface must be replaced by explicit async APIs under the corrected no-public-blocking contract; do not route it through an ordinary Thread.spawn path. Use the explicit async surfaces that already exist for executor-friendly I/O: std:fs.File.open/create/append/open_with/close, std:fs module text/binary helpers, directory snapshots/mutations, target-backed Path queries, and File text helpers, top-level std:process host helpers args()/env()/env_all()/set_env(), std:process.Command.spawn()/status()/output() and Child.wait()/kill() are now awaitable process futures, concrete stdio handle methods such as stdin().read(...)/ stdin().read_async(...) and stdout().write_all(...)/ stdout().write_all_async(...)/stderr().flush()/ stderr().flush_async(), descriptor byte IO and seek methods such as File.read(...), File.read_to_end(...), File.write(...), File.write_all(...), File.flush(), File.seek(...), and the matching aliases File.read_async(...), File.read_to_end_async(...), File.write_async(...), File.write_all_async(...), File.flush_async(), and File.seek_async(...), plus the async network surfaces std:net.TcpStream byte-I/O and metadata/control methods, std:net.AsyncTcpStream, std:net.TcpListener.accept()/ std:net.AsyncTcpListener.accept_async(), or plain std:net.UdpSocket datagram/setup/control methods/ std:net.AsyncUdpSocket. Generic async byte-stream code can use std:io.AsyncReader/AsyncWriter; UDP remains datagram-shaped. Network operation deadlines use std:async.timeout(...) around those explicit async futures today, apart from the dedicated TCP connect-timeout constructors TcpStream.connect_timeout and AsyncTcpStream.connect_timeout; copied timeout method families such as read_timeout_async, write_timeout_async, peek_timeout_async, accept_timeout_async, connected UDP send_timeout_async/recv_timeout_async/peek_timeout_async, or address-aware UDP send_to_timeout_async/recv_from_timeout_async/peek_from_timeout_async are not part of the current API. The executor is a small worker pool with local run queues, stealing, and a global injector; sleep/timeout deadlines are driven by a shared timer driver, today's helper-backed future I/O sources register one-shot completion wakeups with the same reactor core, and the spawn keyword also schedules onto it. Deeper readiness-native provider integration remains planned work. Runtime deployments can tune the pool width with OTTER_FUSION_TASK_WORKERS=N without changing program semantics. Task handles additionally support cooperative cancel() / abort(): cancellation stops future polls at the next suspension point, drops the task state, releases task-held Shared locks, and makes join() resolve to Joined<R> | Panicked | Cancelled. OS-thread Thread.spawn handles deliberately do not have cancel(). detach(), cancel(), and abort() are immediate non-Future handle controls returning null; they are not awaited. The not-awaitable e2e guards cover both ordinary-closure and async-closure Thread.spawn/Task.spawn overloads so neither handle shape can drift into a bare awaitable future. (Stackful, goroutine-style green threads with implicit suspension and no explicit async/await surface are deliberately not planned: they are a second concurrency model in tension with this language's explicit-async design and would require Go-runtime-level syscall handoff and preemption.)

Cross-thread capture — isolation rules

Every capture is independent
  • Captured reference → deep clone at spawn site (uses Clone.clone; requires T: Clone).
  • Captured primitive → value copy.
  • No Clone impl → compile error at the spawn site, pointing at the offending capture.
This is the default isolation boundary. To share, use channels or Shared<T>.

2. Channels — std:sync

The implemented channel is unbounded MPSC. MPMC is reserved for the fan-out runtime slice.

Sender / Receiver API

extend<T> Sender<T> {
  function send(self, value: T): null | ChannelClosed   // non-blocking
}

extend<T> Receiver<T> {
  function recv(self): Future<T | ChannelClosed>   // async — await it
  function try_recv(self): T | null                // non-blocking poll
}

pub struct ChannelClosed;

ChannelClosed is an ordinary marker value and implements Eq, Clone, Hash, ToStr, and std:fmt.Debug. Channel endpoints themselves are runtime handles with deterministic endpoint-release behavior. The implemented constructor is channel<T>(), which returns (Sender<T>, Receiver<T>). The names channel_bounded, channel_mpmc, and channel_mpmc_bounded are reserved in std:sync for the real back-pressure and multi-consumer runtime work; calls to them are compile-time planned-feature diagnostics, and using them as function values diagnoses too. They do not execute placeholder bodies.

Channel receive waits are async. send enqueues onto an unbounded queue and returns at once — it never blocks (it returns null, or ChannelClosed once every receiver is gone). recv() does not park the calling OS thread: it returns a Future<T | ChannelClosed> (see async) that you await. Polling the future pops the next message if one is ready, resolves to ChannelClosed once the queue is drained and every sender has been dropped, otherwise registers the executor's waker and reports Pending so the task suspends and the thread is free to run other work. A later send — or the release of the last sender — wakes the waiter, which re-polls. for await x in rx is the multi-message drain form: it awaits recv() for each step and terminates once the queue is drained and the channel resolves to ChannelClosed. Plain for x in rx is not a channel API and is rejected by the checker. The negative e2e guards cover the immediate non-blocking send() enqueue, the immediate non-blocking try_recv() poll, and the rejected plain receiver loop.
Closed when the last sender is dropped. A channel closes the instant its final Sender is released. Channel endpoints are reference-counted runtime handles whose drop is deterministic and scope-bound (16-memory §8), not a GC-timed finalizer: a Sender captured into a Thread.spawn worker is released the moment that worker returns, and Sender.clone() registers another producer that must also be released. So a producer that finishes its work promptly closes the channel, terminating the consumer — no garbage collection required. 
function consume(rx: Receiver<T>): Future<null> async {
  var msg: T | ChannelClosed = await rx.recv();   // suspends until a message arrives
  match msg {
    T m            => process(m),
    ChannelClosed _ => return null,                // drained and closed
  }
}

try_recv is an immediate non-blocking poll: it checks the queue once without a future, returning T | null (null when empty). Planned bounded variants will apply back-pressure by making send async too. The examples/async_channel_iteration.otter example, mirrored by tests/cases/examples/async_channel_iteration.otter, demonstrates the awaited drain loop.

3. Zero-copy on send

The tracing GC keeps no reference count, so uniqueness is established statically at the send site. The decision is purely local — no runtime check, no atomic op, no whole-program analysis. The compiler picks Move when it can prove the value is not aliased; otherwise it falls back to Clone.

Decision is purely static — no runtime check, no atomic. Cross-thread send is a pointer move plus a write barrier.
What we can't recover with static analysis A runtime reference count could detect uniqueness opportunistically — a value that was aliased earlier but happens to have a single live reference at send time could still move. The tracing GC keeps no such count, so the compiler can only guarantee a move when it sees, locally, that the value never escaped. Anything passing through a function call, heap field, or escaping closure becomes a Clone — even if at runtime the alias is no longer live. T: Clone is therefore required for any channel element type; no Clone impl → compile error at the channel declaration.
channel<dynamic> is rejected dynamic does not implement Clone (see 12-type-logic §5), so the T: Clone bound on channels can't be satisfied. For heterogeneous messages, define a union of the expected variants (channel<Event | Command | Ack>()) so the compiler can validate Clone for each. The same applies to spawn capture of dynamic bindings.

4. Shared<T>

pub struct Shared<T> { ... }

extend<T> Shared<T> {
  function new(value: T): Shared<T>
  // `lock`/`try_lock` are ALWAYS async — `await` them. `body` may itself be
  // `async` and may `await`; the mutex is held across the body's suspension
  // points (it is task-aware, not OS-thread-bound). When `body` is `async`,
  // `lock` awaits it until it resolves under the lock, so `R` denotes the body's
  // final (awaited) value — never a nested `Future`.
  function lock<R>(self, body: (T) => R): Future<R> async
  function try_lock<R>(self, body: (T) => R): Future<R | LockBusy> async
}

pub struct LockBusy;

var state = Shared.new(Counter { value: 0 })

await state.lock { c => c.value = c.value + 1 }
var snapshot = await state.lock { c => c.value }

// The body may itself `await`; the lock is held across the suspension, so the
// critical section spans the awaited work (an async-aware mutex).
var loaded = await state.lock { c async => { c.value = await fetch(); c.value } }

LockBusy is an ordinary marker value and implements Eq, Clone, Hash, ToStr, and std:fmt.Debug. Shared<T> itself remains a runtime handle.

Always async — acquire suspends the task, it never blocks the thread There is exactly one lock primitive and it is async. Acquiring a contended lock suspends the awaiting task (registers the executor's waker and returns Pending) — it never parks the OS thread, so the worker stays free to run other tasks (21-async §6). Waiters are served in FIFO order, so the lock is fair and starvation-free. The acquire is keyed to the task, not the OS thread, so the semantics are identical however the task is driven. There is no read/write variant — Shared<T> is a mutex. A future RwLock<T> would be a separate primitive, and any wait-capable read/write acquisition on that primitive must be an explicit async future; immediate probes must be named try_read/try_write or otherwise documented as non-waiting. Internal registry/cell bookkeeping may contend on host mutexes, but that contention is a runtime-native/no-root implementation boundary; it is not the source-level lock acquisition path.
Implementation note: the body is invoked over a uniform integer/pointer ABI, so a float-typed protected value or body result (e.g. Shared<f64> or a body returning f64) is currently rejected with a clear error — wrap the float in a struct.
Only ordinary non-async Thread.spawn workers cannot lock lock/try_lock are await-only. A ordinary non-async Thread.spawn closure cannot await (§1), so calling lock/try_lock inside one is a compile error. An async Thread.spawn closure (() => Future<R>) may lock — its worker polls the future with a real executor and waker, exactly like a spawn-keyword task. So any of these run a lock-using worker: 
// var h = Thread.spawn(() => state.lock(...))   // ERROR — ordinary worker can't await a lock
var h = spawn async { await state.lock { c => c.value = c.value + 1 } }   // OK — spawn keyword
var h = Thread.spawn { async => await state.lock { c => c.value = c.value + 1 } }   // OK — async Thread.spawn worker
await h
Detachment rule — references can't escape the lock A reference returned from body is Cloned at the return boundary — while the lock is still held, so the snapshot is consistent (no Clone → compile error). The reference passed to body — and any reference reachable through it (e.g. c.x, c.x.y) — is valid only inside the lock; storing it where it outlives the lock (an outer-scoped variable, a struct field, a collection, or an escaping closure) is rejected by escape analysis. To carry data out, store a .clone() — a detached deep copy that is no longer aliased into the cell.
This analysis is the same whether body is ordinary or async: it spans the body's await points, so a reference may not escape across a suspension either. (Any additional restriction specific to async bodies will be called out explicitly; the baseline is identical to the ordinary-body rule.)
Not reentrant A task that holds the lock and awaits lock again on the same Shared<T> deadlocks — the holder is suspended and never releases. This includes re-locking the same cell from within the body after an await. Use try_lock if uncertain.
No poisoning A panic in body — or cancellation of an async body — unwinds and releases the lock; future lockers see whatever state the body left behind. Use try_lock + transactional patterns if consistency matters.

5. Atomics

core:sync/atomic exposes the portable Ordering value contract and runtime-backed atomic handle family. The current surface includes AtomicI32, AtomicI64, AtomicU32, AtomicU64, AtomicBool, and AtomicPtr<T>. These are owned @RefCounted native atomic cells: assigning, cloning, or capturing a handle shares the same cell, and the final strong reference releases the native allocation deterministically.

All handles provide load, store, swap, and compare_exchange. Integer atomics also provide fetch_add/fetch_sub, bool atomics provide fetch_and/fetch_or/fetch_xor, and pointer atomics intentionally omit pointer arithmetic. Invalid operation/order pairs such as load(Release) or store(Acquire) panic before crossing into the runtime. Use Shared<T> for ordinary protected state and atomics for explicit lock-free coordination.

6. Thread safety summary

ConstructThread safety
Local varThread-local — never shared by default.
Module-level var (unwrapped)Unsafe under concurrent access. The language does not synchronize.
Captured-by-spawn valueDeep-cloned at spawn — each thread has its own copy.
ChannelSafe by construction; one message has exactly one owner at a time.
Shared<T>Safe; mutex-protected; one writer at a time.
core:sync/atomic handlesSafe for explicit lock-free coordination; cloned and captured handles share one native atomic cell.

8. Cancellation

No built-in thread cancellation To stop a worker, send a sentinel message or close its input channel and let it observe ChannelClosed. Async cancellation: see 21-async.

9. Examples

import { println } from "std:io"
import { Thread } from "std:thread"
import { channel } from "std:sync"

function producer(tx: Sender<i64>) {
  for n in (Range { current: 0, end: 5 }) {
    tx.send(n)
  }
  // tx drops here; channel closes when all senders are dropped
}

function consumer(rx: Receiver<i64>): Future<null> async {
  for await n in rx {
    await println("got " + (n as str))
  }
}

function main(): Future<null> async {
  var (tx, rx) = channel<i64>()
  var h1 = Thread.spawn { producer(tx) }
  await consumer(rx)
  // `join()` is async — await each handle. The main task suspends rather
  // than parking the OS thread while the producer completes.
  var _ = await h1.join()
}
// Shared counter incremented by many tasks
import { Shared } from "std:sync"

// Because `lock` is async, the worker must be able to `await` — so it is an
// `async` function scheduled with the `spawn` keyword (docs/21), or an async
// `Thread.spawn` closure (§1), NOT an ordinary non-async `Thread.spawn` closure (which
// cannot `await`).
function worker(s: Shared<i64>): Future<null> async {
  for _ in (Range { current: 0, end: 1000 }) {
    await s.lock { /* mutate */ it }
  }
}

function main(): Future<null> async {
  var state = Shared.new(0i64)
  var tasks = List.new<Future<null>>()
  for _ in (Range { current: 0, end: 8 }) {
    var s = state.clone()    // Shared<T> is Clone (clones the handle, same inner)
    tasks.push(spawn worker(s))   // `spawn EXPR` yields a Future<null>
  }
  for t in tasks { await t }
  await println((await state.lock { it }) as str)
}
Shared<T>.clone clones the handle, not the value The handle is a GC-managed pointer to (mutex + inner data); both clones reference the same managed object and therefore lock the same mutex. The GC keeps it alive as long as any clone is reachable.
