25. Language Server (LSP)

lang-lsp — the editor brain. A standalone server that speaks the Language Server Protocol over stdio and reuses liblangc (crates/compiler) so the IDE sees exactly what the compiler sees. Ships with a VS Code extension in editors/vscode.

1. Architecture

The server is one more consumer of the front-end, alongside the CLI and the Cranelift backend. It does not fork the parser or type checker; it calls compiler::sema::analyze on the open buffer and reads the span-keyed side tables the checker already produces for code generation.

The same library the compiler uses answers every editor query.
One source of truth Diagnostics in the editor are the identical lexer / parser / type-checker errors lang check reports. There is no second, drifting analysis.

3. Request pipeline

The server keeps the latest text of each open document (DashMap<Url, String>, full-sync). Every request recompiles that text into a Compiled — the front-end is fast and side-effect-free, so this is simpler and more robust than incremental caching, and always reflects the current buffer. 

didOpen / didChange  ──►  store text  ──►  Compiled::new  ──►  publishDiagnostics
hover / definition   ──►  Compiled::new  ──►  offset_at(pos)  ──►  query side tables

4. How queries are answered

Every AST node carries a unique Span, and the checker keys its results by span. A cursor query becomes "find the smallest span that contains this byte offset," then read its entry:

  • Hover — smallest span in resolutions gives the symbol (and a label: function add, a local's name: type, or a builtin signature); the smallest span in expr_types gives the value type.
  • Definition — the resolution under the cursor is a ValueRes. A Local resolves through the new local_decls table to its binding occurrence; a Function/Method/Global/ StructCtor resolves to its definition's name span.
  • References / rename — scan resolutions for every span mapping to the same target (locals' binding spans are recorded there too, so they are included for free).
The one compiler change this needed A local_decls: HashMap<LocalId, Span> table, populated where locals are bound. It is the minimal, additive piece that makes go-to-definition and rename work for locals — the checker's CheckResults doc already named the LSP as a consumer.

5. Positions: UTF-16 ↔ UTF-8

The protocol counts columns in UTF-16 code units; the compiler works in UTF-8 byte offsets. The server converts in both directions: offset_at (position → byte) for incoming cursors, and position_at / span_to_range (byte → position) for outgoing ranges. A multi-byte character such as é is two UTF-8 bytes but one UTF-16 unit, so the conversion walks chars counting len_utf16().

Semantic tokens convert every token, so they use a precomputed LineIndex (line-start table + binary search) instead of scanning from the top of the file each time.

6. Semantic tokens

The legend declares 13 token types. Each lexer token maps to one: keywords, numbers, strings, comments, and operators come straight from the token kind. Identifiers are classified by the checker's resolutions first (function vs. method vs. variable vs. parameter vs. struct constructor), then fall back to whether the name is a declared type or function, and finally to property for a name following .. The bundled TextMate grammar provides instant coloring before the server attaches; semantic tokens then refine it.

7. VS Code extension

editors/vscode is a thin client over vscode-languageclient:

  • Registers the lang language for .otter files with a TextMate grammar and bracket/comment/indentation rules.
  • Launches lang-lsp over stdio (path configurable via lang.server.path; LSP tracing via lang.trace.server).
  • Provides a Lang: Restart Language Server command for use after rebuilding the server.

8. Build & run

cargo build -p lsp→ target/debug/lang-lsp
cargo test -p lspunit tests for the query layer
npm install && npm run compilein editors/vscode

Put lang-lsp on your PATH (or set lang.server.path), then press F5 in VS Code to launch an Extension Development Host.
