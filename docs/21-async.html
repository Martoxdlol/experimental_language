21. Async

State-machine futures, explicit executor, await as the suspension point. No built-in generator syntax — Iterator/AsyncIterator are implemented by hand.

The two tiers

Shape vs runtime: you can write async on any target; you need std:async to drive it.

1. Future<T>

pub struct Pending;
pub struct Ready<T> { pub value: T }

pub interface Future<Output> {
  function poll(self, ctx: *Context): Ready<Output> | Pending
}
A Future<T> is inert Calling poll advances it; a future that is never polled never runs. Construction creates a state machine — execution happens only when something drives it.

Type ergonomics: Future<null> for "no useful return"; Future<T | E> for fallible async.

2. Context and wakers

extern struct Context {
  waker_data: *u8,
  wake_fn:    extern (*u8) => null,
}
Returning Pending without arranging for a wake is a forever-hung task.

3. async functions

function fetch_data(url: str): Future<str> async {
  var response = await http_get(url)
  response.body
}
Postfix async is a body modifier The async keyword sits between the signature and the body. The return type is written explicitly as Future<T> — there is no auto-wrapping. Calling fetch_data(url) does NOT execute the body — it returns a fresh Future<str>. The compiler turns code between awaits into states.
Interface and impl signatures line up 
interface Fetcher {
  function fetch(self, url: str): Future<str>                  // interface — no body
}

extend MyFetcher: Fetcher {
  function fetch(self, url: str): Future<str> async { ... }    // impl
}
The contract type is identical on both sides; async only annotates the body.

4. await

var v = await fut
  • poll returns Ready<T> → await evaluates to value.
  • poll returns Pending → current async body suspends, returning Pending from its own poll after recording the inner future's waker.
Where await is allowed Only inside an async body (function, closure, or a bare async { ... } block). NOT at module level (only compile-time constants there).
No automatic error propagation If fut: Future<T | E>, the result of await is T | E. Use ? to propagate: (await http_get(url))?.

5. "Forgot to await" lint

A Future<T> created but never awaited, never spawned, and never returned is suspicious. The compiler errors by default on silently-discarded futures.

function fetch_data(): Future<str> async { "data" }

function main() {
  fetch_data()             // ERROR — Future created but unused
  spawn(fetch_data())      // OK
  var f = fetch_data()     // OK — bound
  var _ = fetch_data()     // OK — acknowledged discard
}

6. Executor — std:async

pub function spawn<T>(fut: Future<T>): JoinHandle<T>
pub function block_on<T>(fut: Future<T>): T

import { block_on } from "std:async"
import { println }  from "std:io"

function main() {
  block_on(async {
    var r = await some_top_level_task()
    println(r)
  })
}

The default executor is a work-stealing thread pool with one worker per logical core. JoinHandle<T> is the same type from 20-concurrency.

The bare async { ... } block This is the one place async appears without a signature in front of it. It is a zero-arg inline future literal: the block becomes a Future<T> whose T is the type of the trailing expression. Kept as a deliberate exception so launchers like block_on and spawn don't force (() async => { ... })() ceremony. 
block_on(async { await work() })            // OK — inline future literal
spawn(async { await tick() })               // OK
var fut: Future<i64> = async { 42 }         // OK — value form
Don't block the worker thread A future polled by an executor runs on the executor's worker. The poll body must not block the OS thread for long — return Pending and rely on a waker. Synchronous blocking calls (file I/O, sync DB) should go through a "blocking task" mechanism the executor provides (implementation-defined).

7. Async closures

var f1 = function(x: i64): Future<str> async {
  await sleep(100)
  x as str
}

var f2 = (x) async => {
  await sleep(100)
  x as str
}

// To get the "implicit it" feel, attach the async closure as a trailing closure
// to a launcher like spawn:
spawn { await fetch(it) }              // it: the argument the launcher passes in

The async modifier sits between the signature and the body opener: before { on a function(...), before => on an arrow closure. The bare async { ... } block (see §6) is the one exception — a zero-arg inline future literal kept for ergonomics with launchers like block_on.

Captures follow ordinary closure rules. When passed to spawn, the captured set is subject to cross-thread isolation (20 §1) — captured references are deep-cloned at spawn time. Async closures cannot be extern.

8. Cancellation — by drop

Drop the future = cancel it Dropping a future invokes its Drop impl, which releases any acquired resources (open FDs, pending I/O registrations). select!-style combinators work by polling multiple futures and dropping the losers when a winner completes.
No built-in cancellation token For cooperative cancellation, pass a Shared<bool> or a Receiver<Cancel> to the future and let it check.

9. Timeouts

pub function timeout<T>(fut: Future<T>, duration_ms: i64): Future<T | TimedOut>

pub struct TimedOut;

Races fut against a timer. Whichever finishes first wins; the other is dropped.

10. AsyncIterator<T>

pub interface AsyncIterator<T> {
  function next_async(self): Future<Item<T> | Done>
}

function process(stream: AsyncIterator<i64>): Future<null> async {
  for await n in stream {
    println(n as str)
  }
}

Desugaring:

{
  var __it = stream
  loop {
    match (await __it.next_async()) {
      Item { value } => { var n = value; ... loop body ... },
      Done           => break,
    }
  }
}
No generator syntax No yield, no gen. yield is reserved but unused. Implement AsyncIterator<T> by hand: 
pub struct Ticker {
  pub current:  i64,
  pub end:      i64,
  pub delay_ms: i64,
}

extend Ticker: AsyncIterator<i64> {
  function next_async(self): Future<Item<i64> | Done> {
    async {
      if self.current >= self.end {
        Done
      } else {
        await sleep(self.delay_ms)
        var v = self.current
        self.current = self.current + 1
        Item { value: v }
      }
    }
  }
}

11. Async and panics

SiteEffect
block_on(fut)Calling thread panics.
spawn(fut)Task ends; JoinHandle.join returns Panicked.

Other in-flight futures on the same executor are unaffected.

12. Composition primitives — library land

Specific combinators (join, race, select) are stdlib additions, not core language. The minimum guarantees:

  • await exists and behaves as described.
  • spawn exists and returns a JoinHandle.
  • Future<T> has the interface shape above.
  • Context interoperates with C event loops.

13. Summary

  • Future<T> is an inert state machine.
  • Postfix async on a function body produces one; await drives one inside another. The return type is written explicitly as Future<T>.
  • Futures must be spawned or awaited; ignoring them is a compile error.
  • The default executor is a work-stealing pool; block_on runs a top-level future.
  • AsyncIterator<T> + for await for async streams. No generator syntax.
  • Cancellation by drop; timeouts via timeout(...).
  • Async closures use postfix async too; bare async { ... } is a zero-arg inline future literal.
