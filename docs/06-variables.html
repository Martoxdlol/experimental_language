6. Variables and Mutability

One keyword: var. Every binding is mutable. Restrictions come from module visibility, not from variable annotations.

At a glance

One keyword, one shape — the type annotation is the only optional piece.
var name: str = "John Doe"
var age = 30           // type inferred — i64 (default literal type)
var price: f32 = 19.99

name = "Jane Doe"      // mutation

1. Declaration syntax

var <name>          : <type> = <expr>     // explicit
var <name>                    = <expr>     // inferred
No uninitialized bindings Primitives have no implicit default value. var x: i64 alone is a compile error — you must write var x: i64 = 0. This is intentional; see 02-types §8.

2. Mutation

Any binding can be reassigned, including to a value of a different concrete type — as long as the new type fits the declared (or inferred) type.

Reassignment within the declared type — fine. Reassignment that escapes the type — rejected.

3. Scoping & shadowing

Lexical scoping. A block { ... } introduces a new scope. Inner bindings shadow same-named outer bindings.

Shadowing only crosses block boundaries. Two vars with the same name in the same block is an error.
function example() {
  var x: i64 = 5
  if x > 0 {
    var x: str = "positive"   // shadows; type can differ
    print(x)
  }
  // x is still i64 here
}

4. Module-level variables

Variables declared at module top level are persistent storage. Their initializer must be a compile-time constant expression.

Module-level values are baked into the binary — no runtime initializer races.
pub var MAX_RETRIES: i32 = 5
var counter: i64 = 0
pub var DEFAULT_CONFIG = Config { debug: false, port: 8080 }

Visibility

FormEffect
var FOOModule-private.
pub var FOOVisible to importers — read AND write.
No read-only visibility A pub var is read and writeable by importers. The language does not distinguish read-only from read-write at the visibility layer. If you want read-only-from-outside semantics, expose a getter function and keep the var private. Multi-thread writes need Shared<T> — see 20-concurrency.

5. Assignment is a statement

Assignment does not produce a value:

var y = (x = 5)   // parse error — assignment is not an expression

For the expression-vs-statement rules, see 07-expressions.

6. Pattern bindings

var (x, y) = point
var (a, ..rest) = quad             // tuple rest binding — rest is a sub-tuple
var Person { name, age } = alice
var Pair(a, b) = pair

Each name introduced is a normal var binding, individually mutable.

Patterns in var must be irrefutable They must always match. To match conditionally use match or if v is T. List patterns like [head, ..tail] are refutable (an empty list doesn't match), so they are not valid in var — use match instead.

7. Reference semantics — what assignment does

Same model as every refcounted language. Use .clone() to break aliasing.
var a = Person { name: "Alice", age: 30 }
var b = a             // b refers to the same heap object as a (RC bumped)
b.age = 31
print(a.age as str)   // 31 — a and b alias

var c = a.clone()     // independent copy (requires Clone)
c.age = 32
print(a.age as str)   // 31 — c is independent
Memory model This aliasing-with-mutation model is the standard one for refcounted languages and matches the full memory model in 16-memory. Clone is defined in 15-operators.
