18. Standard Library

Two tiers — core:* (needs only an allocator) and std:* (needs an OS). Nothing is auto-imported: built-in syntax works without an import, but every name — including List — is imported (see the prelude rule).

1. The two tiers

This chapter documents the data-oriented parts of the core: tier. List/Map/Set live in core:collections (imported by name) and use a deterministic default hasher. Interfaces are in 15-operators; concurrency in 20/21.

2. Failure semantics across stdlib

Three distinct failure shapes, picked by what the caller actually needs to know:

The third shape — panic — is for programming-bug invariants only; see 14-panics.
The [] exception Indexing operators (list[i], map[k]) panic on missing/out-of-range. The .get(...) form returns T | null. Indexing is for known-valid access; get is for fallible access.
No implicit null → Error promotion T | null and T | Error are different shapes. The compiler does not insert a conversion between them at ? sites. If a function calls a T | null API but returns T | E, the caller writes the lift explicitly: if v is null { return ... } v as T — or wraps it once via a tiny helper. This keeps the choice between "no reason" and "with reason" deliberate.

3. The Error interface

Errors are still ordinary values living in unions (chapter 13). This interface is the shape contract that lets generic code — loggers, context-wrappers, panic-on-error helpers — consume any error type without knowing its concrete kind.

pub interface Error: ToStr {
  function message(self): str
  function cause(self): Error | null
}

Composition: Error: ToStr means every Error-implementing type also implements ToStr. ToStr (chapter 15) is the language's single stringification path — no separate Display / Debug split. to_str(self) renders the value; message(self) is just this error's own short text (without walking the chain).

Canonical shapes

Two recommended layouts. Pick whichever fits the failure modes you actually expose.

Kinded — when there are several distinct failure modes a caller may discriminate. 
pub struct IoError {
  pub kind:    IoErrorKind,
  pub message: str,
}

pub union IoErrorKind =
    NotFound | PermissionDenied
  | ConnectionRefused | TimedOut
  | UnexpectedEof | Interrupted
  | Other
Flat — when there is one failure mode plus optional context. 
pub struct ParseError {
  pub message:  str,
  pub position: i64,
}
Forward-compatibility for kinded errors Always include an Other variant in a public *Kind union, and always handle it with an else => arm in match. Adding new variants to the union later is then non-breaking for callers that follow the rule.

Annotating errors — Annotated and with_context

To add a breadcrumb when crossing a layer boundary, wrap any error in Annotated. The wrapped value still implements Error, so chains are arbitrarily deep.

pub struct Annotated {
  pub note:   str,    // this layer's contribution
  pub source: Error,  // the wrapped lower-level error
}

extend Annotated: Error {
  function message(self): str         { self.note }
  function cause(self):   Error | null { self.source }
  function to_str(self):  str          { self.note + ": " + self.source.to_str() }
}

// Free helper: lift a fallible result, attaching context only on failure.
pub function with_context<T, E: Error>(
  value: T | E,
  note: str,
): T | Annotated {
  if value is E {
    Annotated { note: note, source: value as E }
  } else {
    value as T
  }
}
Usage 
function load(path: str): Config | Annotated {
  var bytes  = with_context(read_file(path),     "loading config")?
  var parsed = with_context(parse(bytes),        "parsing config")?
  with_context(validate(parsed),                 "validating config")?
}
Each with_context attaches a layer message; ? propagates the resulting Annotated; the caller can walk cause() to recover the full chain.
No automatic source-location capture Errors do not attach a file/line when constructed — this is by design, to keep error values cheap and free of hidden allocations. Debug-build panics print stack traces (chapter 14); value-errors instead use Annotated chains to record where each layer added context. Tooling that wants captured locations can do so explicitly by adding a field to its own error struct.

5. List<T>

Lives in core:collections (allocator-only, freestanding-safe): import { List } from "core:collections". The […] literal needs no import; naming List does.

var a: List<i64> = [1, 2, 3]
var b = List.new<i64>()
var c = List<i64>()          // shorthand — same as List.new<i64>()

6. Map<K, V>

Lives in core:collections: import { Map } from "core:collections". It uses a deterministic default hasher (core:hash) — fast and freestanding-safe, but not HashDoS-resistant; supply a keyed hasher for untrusted keys.

var a: Map<str, i64> = { "x": 1, "y": 2 }
var b = Map.new<str, i64>()
var c = Map<str, i64>()         // shorthand
Map literal vs block { ... } is overloaded. The parser tries a map-literal parse first; it commits on seeing <key-expression> :. {} is the empty block — use Map.new<K, V>() for an empty map. A bare { ... } with no : is a block. Inside call-argument position, { "x": 1 } is a map literal.

Spread & collision rule

var defaults = { "host": "localhost", "port": 8080 }
var override = { "port": 9090 }
var final    = { ..defaults, ..override }
// { "host": "localhost", "port": 9090 } — rightmost wins on collision

var with_extras = { ..defaults, "tls": true, ..override }
// { "host": "localhost", "port": 9090, "tls": true }

7. Item<T> & Done

pub struct Item<T> {
  pub value: T,
}

pub struct Done;

Used by the iterator protocol: Iterator<T>.next returns Item<T> | Done. Wrapping the value in Item<T> avoids the ambiguity that would arise if T itself could be null.

8. Iterator<T>

pub interface Iterator<T> {
  function next(self): Item<T> | Done
}

Contract: each call to next produces an Item<T> or Done. Once Done, subsequent calls should also return Done.

pub struct Range {
  pub current: i64,
  pub end:     i64,
}

extend Range: Iterator<i64> {
  function next(self): Item<i64> | Done {
    if self.current >= self.end {
      Done
    } else {
      var v = self.current
      self.current = self.current + 1
      Item { value: v }
    }
  }
}

for n in (Range { current: 0, end: 5 }) {
  print(n as str)
}

9. Buffer — extern struct

extern struct Buffer {
  data: *u8,
  size: u64,
}
Because Buffer is extern
  • Passes to/from extern functions by value or pointer, no shim.
  • Bytes live on the foreign heap — manual alloc/free; GC does not trace.
  • Cannot implement interfaces.
  • Cannot be a generic type argument (no object header).

alloc(size: u64) staticBuffer | nullForeign-heap; null on OOM

var maybe = Buffer.alloc(1024u64)
if maybe is null {
  // allocation failed
} else {
  var buf = maybe as Buffer
  buf.set(0u64, 65u8)        // 'A'
  buf.free()
}

11. std:io — printing & IO

import { print, println } from "std:io"

print("hello")        // no trailing newline
println("hello")      // appends '\n'

Both take str. To print non-strings, convert first via as str for numeric primitives or implement a project-local stringification interface.

13. What is NOT in this version

Intentional omissions
  • No regular expressions.
  • No JSON (write a parser; extern is available).
  • No time / date (likely a future std:time).
  • No Display / Debug split — ToStr (chapter 15) is the single stringification path; Error just requires it as a super-interface.
  • No format! macro — string interpolation (chapter 1) is the only formatting sugar.
  • No blessed Result<T, E> alias — write T | E directly. Type aliases for project-local error types stay local.
  • No async filesystem / networking adapters.
Surface kept small on purpose. These may land as separate std:* modules later.
