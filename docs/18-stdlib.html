18. Standard Library

Two tiers — core:* (compiler/runtime substrate) and std:* (official toolchain library, portable or target-backed). Nothing is auto-imported: built-in syntax works without an import, but every name — including List — is imported (see the prelude rule).

1. The two tiers

core: is small because it carries compiler/runtime contracts. Portable but ordinary library APIs belong in std:, even when they do not need an OS.

2. Implementation model

The standard library is a toolchain package with a curated module catalog. Its public import paths stay stable (std:error, std:io, std:fs, ...), but each module can be implemented in one of three ways:

KindMeaningExamples
OtterAPI and behavior are authored in Otter Fusion source.std:error, std:bytes, std:fmt, std:time.Duration, std:fs.Path, std:hash, std:http, std:rand.SeededRng
RustBackedThe importable surface is a marker or wrapper; behavior is supplied by Rust runtime/compiler intrinsics.std:io.print, std:io.eprintln, core:prelude.panic, std:process.exit/abort, future target-only hooks
MixedOtter Fusion definitions layer a safe API over Rust-backed runtime hooks.std:io, std:time.Instant/SystemTime, std:fs.File handles and file helpers, std:process host environment/execution helpers, std:rand.OsRng/ThreadRng, core:ffi.CString, channels, Shared

This split is intentional. Compiler-privileged substrate stays in core:*; ordinary library shapes and policy live in std:* even when they are fully portable. Low-level host integration, allocation primitives, OS calls, atomics, and scheduler hooks may still be implemented in Rust. The compiler's stdlib catalog records the module path, tier, implementation kind, and exported names; import resolution consumes that catalog instead of hardcoding each module inline. Otter-authored toolchain definitions are kept in crates/compiler/src/sema/stdlib_src/core and crates/compiler/src/sema/stdlib_src/std, then collected into hidden module-local owners under the private __builtins__ root before the catalog builds public views. The contributor workflow for adding or replacing modules is specified in 29-extending-stdlib.

Target providers The active toolchain currently ships one built-in provider, but the design is provider-based. A future target can supply its own std:* provider (for example POSIX, WASI, embedded, browser, or game-console targets) while preserving the same core:* compiler substrate. Provider selection changes which modules are available and which Rust/Otter implementations back them; it does not change the import syntax.

3. Failure semantics across stdlib

Three distinct failure shapes, picked by what the caller actually needs to know:

The third shape — panic — is for programming-bug invariants only; see 14-panics.
The [] exception Indexing operators (list[i], map[k]) panic on missing/out-of-range. The .get(...) form returns T | null. Indexing is for known-valid access; get is for fallible access.
No implicit null → Error promotion T | null and T | Error are different shapes. The compiler does not insert a conversion between them at ? sites. If a function calls a T | null API but returns T | E, the caller writes the lift explicitly: if v is null { return ... } v as T — or wraps it once via a tiny helper. This keeps the choice between "no reason" and "with reason" deliberate.

4. The Error interface

Errors are still ordinary values living in unions (chapter 13). This interface is the shape contract that lets generic code — loggers, context-wrappers, panic-on-error helpers — consume any error type without knowing its concrete kind.

The error surface is imported from std:error:

import { Error, Annotated, with_context } from "std:error"

pub interface Error: ToStr {
  function message(self): str
  function cause(self): Error | null
}

Composition: Error: ToStr means every Error-implementing type also implements ToStr. ToStr (chapter 15) is the language's interpolation and cast-to-string path. Library APIs that need user-facing or developer-facing rendering can additionally use std:fmt.Display and std:fmt.Debug. to_str(self) renders the value; message(self) is just this error's own short text (without walking the chain).

Canonical shapes

Two recommended layouts. Pick whichever fits the failure modes you actually expose.

Kinded — when there are several distinct failure modes a caller may discriminate. 
pub struct IoError {
  pub kind:    IoErrorKind,
  pub message: str,
}

pub union IoErrorKind =
    NotFound | PermissionDenied
  | ConnectionRefused | IoTimedOut
  | UnexpectedEof | Interrupted
  | OtherIo
Flat — when there is one failure mode plus optional context. 
pub struct ParseError {
  pub message:  str,
  pub position: i64,
}
Forward-compatibility for kinded errors Always include an Other variant in a public *Kind union, and always handle it with an else => arm in match. Adding new variants to the union later is then non-breaking for callers that follow the rule.

Annotating errors — Annotated and with_context

To add a breadcrumb when crossing a layer boundary, wrap any error in Annotated. The wrapped value still implements Error, so chains are arbitrarily deep.

pub struct Annotated {
  pub note:   str,    // this layer's contribution
  pub source: Error,  // the wrapped lower-level error
}

extend Annotated: Error {
  function message(self): str         { self.note }
  function cause(self):   Error | null { self.source }
  function to_str(self):  str          { self.note + ": " + self.source.to_str() }
}

extend Annotated: Debug {
  function debug(self):   str          { "Annotated { note: \"" + self.note + "\", source: " + self.source.to_str() + " }" }
}

// Free helper: lift a fallible result, attaching context only on failure.
pub function with_context<T, E: Error>(
  value: T | E,
  note: str,
): T | Annotated {
  if value is E {
    Annotated { note: note, source: value as E }
  } else {
    value as T
  }
}
Usage 
function load(path: str): Config | Annotated {
  var bytes  = with_context(read_file(path),     "loading config")?
  var parsed = with_context(parse(bytes),        "parsing config")?
  with_context(validate(parsed),                 "validating config")?
}
Each with_context attaches a layer message; ? propagates the resulting Annotated; the caller can walk cause() to recover the full chain.

Annotated also implements std:fmt.Debug so diagnostics can show the wrapper and its source in one line. It intentionally does not provide generic clone, equality, or hashing: the wrapped source is only known as an Error interface object, and Error does not require those value semantics.

No automatic source-location capture Errors do not attach a file/line when constructed — this is by design, to keep error values cheap and free of hidden allocations. Debug-build panics print stack traces (chapter 14); value-errors instead use Annotated chains to record where each layer added context. Tooling that wants captured locations can do so explicitly by adding a field to its own error struct.

7. Map<K, V>

Lives in core:collections because map literals, indexing, and iteration use runtime-recognized collection layout: import { Map } from "core:collections". It uses a deterministic toolchain hasher — fast and portable, but not HashDoS-resistant. Explicit keyed hasher values live in std:hash; keyed map/set construction remains planned.

var a: Map<str, i64> = { "x": 1, "y": 2 }
var b = Map.new<str, i64>()
var c = Map<str, i64>()         // shorthand
Map literal vs block { ... } is overloaded. The parser tries a map-literal parse first; it commits on seeing <key-expression> :. {} is the empty block — use Map.new<K, V>() for an empty map. A bare { ... } with no : is a block. Inside call-argument position, { "x": 1 } is a map literal.

Spread & collision rule

var defaults = { "host": "localhost", "port": 8080 }
var override = { "port": 9090 }
var final    = { ..defaults, ..override }
// { "host": "localhost", "port": 9090 } — rightmost wins on collision

var with_extras = { ..defaults, "tls": true, ..override }
// { "host": "localhost", "port": 9090, "tls": true }

Lives in core:collections because the compiler tracks the runtime-recognized collection shape for construction, tracing, and future set literal support: import { Set } from "core:collections". Set literal syntax is not implemented yet; use Set<T>() and insert.

9. Item<T> & Done

pub struct Item<T> {
  pub value: T,
}

pub struct Done;

Used by the iterator protocol: Iterator<T>.next returns Item<T> | Done. Wrapping the value in Item<T> avoids the ambiguity that would arise if T itself could be null.

10. Iterator<T>

pub interface Iterator<T> {
  function next(self): Item<T> | Done
}

Contract: each call to next produces an Item<T> or Done. Once Done, subsequent calls should also return Done.

pub struct Range {
  pub current: i64,
  pub end:     i64,
}

extend Range: Iterator<i64> {
  function next(self): Item<i64> | Done {
    if self.current >= self.end {
      Done
    } else {
      var v = self.current
      self.current = self.current + 1
      Item { value: v }
    }
  }
}

for n in (Range { current: 0, end: 5 }) {
  print(n as str)
}

11. Buffer — extern struct

extern struct Buffer {
  data: *u8,
  size: u64,
}
Because Buffer is extern
  • Passes to/from extern functions by value or pointer, no shim.
  • Bytes live on the foreign heap — manual alloc/free; GC does not trace.
  • Cannot implement interfaces.
  • Cannot be a generic type argument (no object header).

13. std:bytes — managed byte buffers

import { Bytes } from "std:bytes"

var b = Bytes.new()
b.push(0x41u8)
b.size()              // 1
b.get(0)              // u8 | null
b.set(0, 0x42u8)     // bool
b.pop()               // u8 | null
b.remove_at(0)        // u8 | null
b.truncate(1)         // shrink in place
b.clear()             // empty the buffer
b.iter()              // Iterator<u8>
b.cursor()            // BytesCursor snapshot

Bytes is an ordinary managed-heap library container, so it lives in std:, not core:. It currently provides new, with_capacity, from_str UTF-8 encoding, size, is_empty, get, set, push, pop, remove_at, append, truncate, clear, append_iter, slice, decode_utf8, iter, and cursor. Bytes also implements std:io.Writer as an in-memory sink: write and write_all append bytes, and flush is a no-op. BytesCursor snapshots a Bytes value and implements std:io.Reader and std:io.Seeker for in-memory reads; cursor snapshots implement equality, clone, hash, stringification, and debug rendering. decode_utf8 validates strict UTF-8 and returns str | Utf8Error. Raw-buffer views remain planned.

14. std:io — printing & IO contracts

import { Bytes } from "std:bytes"
import { print, println, eprint, eprintln, stdin, stdout, stderr } from "std:io"

print("hello")        // no trailing newline
println("hello")      // appends '\n'
eprint("warning")     // stderr, no trailing newline
eprintln("warning")   // stderr, appends '\n'

stdout().write(Bytes.from_str("raw bytes"))
stdin().read_to_end(Bytes.new())
stderr().flush()

Both take str. To print non-strings, convert first via as str for numeric primitives or implement a project-local stringification interface.

import { Reader, Writer, Seeker, IoError, SeekFrom } from "std:io"

interface Reader {
  function read(self, buf: Bytes): i64 | IoError
  function read_to_end(self, buf: Bytes): i64 | IoError
}

interface Writer {
  function write(self, buf: Bytes): i64 | IoError
  function write_all(self, buf: Bytes): null | IoError
  function flush(self): null | IoError
}

interface Seeker {
  function seek(self, pos: SeekFrom): i64 | IoError
}

std:io is a mixed module: the shared contracts and IoError shape are authored in Otter Fusion, while print, println, eprint, and eprintln lower to runtime intrinsics. stdin(), stdout(), and stderr() return target-backed stream handles for byte-oriented reads, writes, and flushes. SeekFrom and IoErrorKind provide direct equals / eq, overloaded ==, clone, hash, stringification, and debug helpers; IoError implements Error, equality, clone, hash, and debug rendering. BufReader and BufWriter provide interface-object buffered adapters over any Reader or Writer.

15. std:fmt — formatting contracts

import { Display, Debug, FmtSink, FmtError } from "std:fmt"

std:fmt is an Otter-authored contract module. It exports Display: ToStr for user-facing rendering, Debug for developer-facing rendering, FmtSink for incremental string writes, and FmtError for sink failures. FmtError is itself an std:error.Error value and implements equality, clone, hash, and diagnostic debug rendering. std:bytes.Bytes implements FmtSink as the standard in-memory UTF-8 formatting sink. This is library surface only: interpolation and value as str still use ToStr, and there is no format! macro. Pure stdlib value types such as Bytes, Duration, time values, Path, Json, network identifier values, HTTP values, and std runtime marker/result values implement Debug. Generic collections implement diagnostic rendering when their contents can be rendered: List<T: Debug>, Set<T: Eq + Debug>, and Map<K: Eq + Hash + ToStr, V: Debug>. Primitive Debug remains planned because it requires intrinsic interface-object support.

17. What is NOT in this version

Intentional omissions
  • No regular expressions.
  • No JSON parser or stricter canonical serializer in stdlib; std:json provides the shared value tree plus compact and pretty escaped rendering.
  • No public keyed map/set hasher integration yet; std:hash provides deterministic hasher and byte-stream helpers over the current Hash contract.
  • No cryptographic-strength RNG API guarantee or richer statistical distributions yet; std:rand provides deterministic seeded RNGs, OS-backed entropy handles, per-value generators, and basic uniform distribution helpers.
  • No HTTP client/server or wire parser yet; std:http provides shared request/response value types only.
  • No network sockets, DNS, IDNA handling, or stricter URL canonicalizer yet; std:net:types provides portable identifier values plus IPv4, IPv6 including scoped zone IDs, socket-address, URI, and URL parsing.
  • No provider-backed timezone database or local-time lookup yet; std:time currently provides Duration, monotonic Instant, wall-clock SystemTime, timezone values, validated/parsed DateTime values, and UTC/fixed-offset system-time conversion.
  • No format! macro or format-string language — std:fmt provides contracts only; interpolation remains the built-in formatting sugar.
  • No blessed Result<T, E> alias — write T | E directly. Type aliases for project-local error types stay local.
  • No async filesystem / networking adapters.
Surface kept small on purpose. These may land as separate std:* modules later.
