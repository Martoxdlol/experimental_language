9. Functions and Closures

One function keyword spans named functions, anonymous functions, and methods. Arrow closures ((x) => ...) and trailing-closure blocks (xs.map { it * 2 }) layer lighter syntax on top.

1. Function declaration

Signature parts. Only the keyword, name, and param list are required.
pub function add(a: i64, b: i64): i64 {
  a + b
}

function get_ratio(current: f64, total: f64): f64 {
  if total == 0.0 {
    return 0.0
  }
  current / total
}

2. Generic functions

function identity<T>(value: T): T {
  value
}

function bigger<T: Ord>(a: T, b: T): T {
  if a > b { a } else { b }
}

function map<I, O>(xs: List<I>, f: (I) => O): List<O> {
  var out = List.new<O>()
  for x in xs {
    out.push(f(x))
  }
  out
}

See 11-generics for bounds, monomorphization, and dispatch.

3. Function-type syntax

var f: (i64) => i64                = function(x: i64): i64 { x * 2 }
var combine: (i64, i64) => i64     = function(a: i64, b: i64): i64 { a + b }
type IntFn = (i64) => i64           // names not part of the type

// C-ABI function type, used in FFI
type CCallback = extern (data: *u8, size: u64) => i32
One arrow, three positions => means "produces" in three different places: function type ((i64) => i64 — takes i64, produces i64), arrow closure ((x) => x * 2 — given x, produces x*2), and match arm (Some(n) => n * 2 — on this pattern, produces n*2).

4. Anonymous functions

Anonymous functions use the same function keyword as named ones — they're just expressions. Most explicit; no inference needed.

var double = function(x: i32): i32 { x * 2 }
var add    = function(a: i64, b: i64): i64 { a + b }

5. Arrow closures — (x) => ...

A closure is an expression that produces a function value. Types are inferred from the expected type at the use site; annotations are optional.

(x) => x * 2                       // single expression body
(a, b) => a + b                    // multi-param
() => 42                           // zero-param
(x) => { var y = x + 1; y * y }    // block body — last expression is the value
(x: i32): i32 => x + 1             // explicit annotations allowed

An arrow closure and the equivalent function(...) { ... } are the same kind of value — a value of some (P...) => R function type. They differ only in how much the compiler infers.

The arrow separates the signature from the body. Everything after => is one expression — either bare, or a block.

6. Trailing closures & implicit it

When the last argument of a call is a closure, you can move it outside the parens as a { ... } block. Inside the block, write params => body for explicit parameters, or use the implicit binding it when there's exactly one parameter.

Trailing closures attach to the call that immediately precedes them. Implicit it only inside a trailing block with no declared params.
// All four below are the same call:
numbers.map((x) => x * 2)
numbers.map(function(x: i32): i32 { x * 2 })
numbers.map { x => x * 2 }
numbers.map { it * 2 }

// Chains read top-to-bottom:
people
  .filter { it.age >= 18 }
  .map    { it.name }
  .sort_by { a, b => a - b }
Trailing-closure ambiguity in headers In the bare top-level expression of if / while / for / match headers, a trailing closure is not allowed unparenthesized — the parser can't tell whether the { starts the closure or the header's body. Wrap the call: for n in (xs.map { it * 2 }) { print(n as str) }. Same rule as the struct-literal ambiguity — see 07-expressions §2.

How the parser picks the form

  1. A { immediately following a call f(...), a method reference x.method, or an index x[i] begins a trailing closure — that block becomes the last argument.
  2. A { immediately following a bare type-name identifier (Foo { ... } or Foo<T> { ... }) is a struct literal when the brace contents look like fields (name: / name, / name } / ..base / empty); otherwise the { doesn't continue the expression.
  3. Inside a trailing-closure block, the parser attempts to parse a parameter list followed by =>. If it succeeds, those are the closure's parameters. Otherwise the block is the body — it may reference it when the expected arity is 1; for arity 0 the body has no it; for arity ≥ 2 an explicit param list is required.
  4. A { elsewhere (after =, after return, in operator position, etc.) is a block expression, not a closure.

7. Captures

Mental model: every captured variable is captured by reference; primitives just sit inline in the cell.
extern callbacks cannot capture A C function pointer has no environment slot. To pass state to a C callback, use the conventional void* user-data parameter (typed as *T in this language). See 19-ffi.

8. Async functions and async closures

async is a postfix body modifier: it sits between the signature and the body opener. The return type is written explicitly as Future<T>. Bodies may use await. See 21-async.

function fetch_data(url: str): Future<str> async {
  var d = await fetch(url)
  d.body
}

var fut  = function(x: i64): Future<str> async { var d = await fetch(x); d.body }
var fut2 = (x) async => { var d = await fetch(x); d.body }

// As a trailing closure to a launcher:
spawn { await fetch(it) }              // implicit it inside the trailing block

One rule across every form: async goes after the signature and before the body opener — before { on a function(...), before => on an arrow closure. The type of an async closure is (...) => Future<R>.

The one exception is the bare async { ... } block — a zero-arg inline future literal that is awaited or spawned by surrounding async code. See 21-async §6.

9. Calling syntax recap

foo(a, b)                 // free function
foo(a) { it + 1 }         // trailing closure as the last argument
person.greet()            // method (instance)
List.new<i64>()           // static / namespaced function
List<i64>()               // type-as-constructor shorthand for List<i64>.new() — see §10
((x) => x + 1)(5)         // call a closure expression

Methods and static functions share the same function keyword — they differ only by being inside an extend block and (for methods) taking self as the first parameter. See 10-interfaces.

10. Type-as-constructor shorthand

For any type T that exposes a new static method, T(args) is a parse-time rewrite for T.new(args).

A two-token rewrite — no new type-system machinery.
var xs = List<i64>()              // → List<i64>.new()
var m  = Map<str, i64>()          // → Map<str, i64>.new()
var c  = Pool<Conn>(size = 16)    // → Pool<Conn>.new(size = 16)

extend MyCache: ... {
  function new(size: i64): MyCache | InvalidSize {
    if size <= 0 { InvalidSize } else { MyCache { ... } }
  }
}

var c = MyCache(16)?      // c: MyCache, after `?` propagates InvalidSize

11. No variadics / defaults / named args

Fixed grammar — positional, exact arity To approximate optional parameters, accept a struct argument with a spread default. To approximate variadic input, accept a List<T>.

12. Recursion

Direct and mutual recursion are supported. Functions are visible throughout their declaring module regardless of declaration order — there is no top-down restriction.

13. Diverging functions

A function that never returns (always panics, always loops) has an unreachable end-of-body. The compiler infers the return type as never:

function fail(msg: str): null {
  panic(msg)
}
Never is universal Never is a subtype of every type, so a diverging function can sit anywhere any return type is expected. See also 08-control-flow §5.
