14. Panics

A panic terminates the current thread immediately. Not catchable — no try/catch, no recover. Use panics only for programming bugs and irrecoverable conditions.

1. Explicit panic

pub function panic(message: str): never

function require_positive(n: i64): i64 {
  if n <= 0 {
    panic("expected positive, got " + (n as str))
  }
  n
}
The never return type never is a subtype of every type, so a panic(...) call can appear anywhere any value is expected. The companion panic_with(value: T) attaches a structured value (visible to debugger / platform handler) but the language never inspects it.

3. Behavior of a panicking thread

The unit of fault isolation is the thread.

4. Drop during a panic

No double-panic support A Drop impl that itself panics during finalizer-queue execution aborts the entire process. Keep Drop impls infallible — that is the user's responsibility.
Drop during a panic Stack unwinding does not call Drop synchronously. It releases stack roots; objects only reachable from the panicking thread become unreachable and follow the regular finalizer-queue path (eventual, unordered, best-effort). See 16-memory §8. For resources that must be released before the thread dies, do so explicitly before reaching the panic point.

5. Integer overflow

Same families exist on every integer type for add, sub, mul, div, rem, neg, shl, shr.

6. Float behavior

Floats never panic Floats follow IEEE 754 strictly. ÷0 → ±∞ · 0/0 → NaN · out-of-range → ±∞ or NaN · NaN comparisons return false. The only float-panic case is f as i* for NaN or out-of-range.

7. Catchable boundary — joining threads

Spawned threads are the unit of fault isolation. A worker thread that panics is observable by its spawner via the join API:

var handle = spawn(function() { ... })
var result = handle.join()
match result {
  Joined { value }     => print("ok: " + value),
  Panicked { message } => print("worker died: " + message),
}

Joined<T> and Panicked are unit/wrapper structs provided by stdlib. This is the only way to "recover" from a panic: isolate the fallible code in its own thread and join.

8. Style

  • Use panic(...) for invariants you believe are unbreakable.
  • Use T | Error + ? for expected failure paths (user input, network errors, missing keys you intend to handle).
  • Reserve as between union variants for paths you have already narrowed with is/match; otherwise prefer match.
  • Do not use panics for control flow.
