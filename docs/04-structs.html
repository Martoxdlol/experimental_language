Nominal types that group fields. Three forms — record, tuple, unit — sharing construction, visibility, and destructuring rules.

1. Three forms at a glance

All three are nominal — two structs with identical layouts are still different types.

2. Record structs

pub struct Person {
  pub name: str,
  age: i32,             // private to the defining module
}

Every field has its own visibility. Fields default to private; pub exposes them. Field separator is comma — trailing comma allowed.

Construction

var alice = Person {
  name: "Alice",
  age:  30,
}

All fields must be initialized — there are no defaults. If any field is private to another module, construction from outside that module is rejected.

Smart constructors via extend

For initialization that may fail, normalize input, or fetch from a pool — define a new static method via extend, then use the type-as-constructor shorthand:

extend Person {
  function new(name: str, age: i32): Person | InvalidAge {
    if age < 0 { InvalidAge } else { Person { name, age } }
  }
}

var alice = Person("Alice", 30)?    // same as Person.new("Alice", 30)?
Type-as-constructor shorthand T(args) is purely syntactic sugar for T.new(args) (see 09-functions §10). It does not constrain what new returns.

Field init shorthand & spread

Both forms are pure construction — they do not move the source.

3. Tuple structs

A nominal type whose fields are positional:

pub struct Pair(pub i64, pub i64)
pub struct Wrapper<T>(T)

var p = Pair(3, 4)
var w = Wrapper(42)

await print(p.0 as str)
await print(p.1 as str)
Tuple struct ≠ anonymous tuple Tuple structs are nominal — distinct from any other tuple struct with the same shape. Anonymous tuples (05-tuples) are structural. Use tuple structs when the name matters; tuples when only the shape does.

4. Unit structs

pub struct Red;
pub struct Green;
pub struct Blue;

var c: Red | Green | Blue = Red    // mentioning the name constructs the value
pub type Color = Red | Green | Blue

Unit structs are the standard way to enumerate distinguishable variants. The bare name in expression context constructs the unique value.

5. Generic structs

pub struct Box<T> {
  pub value: T,
}

pub struct Pair<A, B> {
  pub first:  A,
  pub second: B,
}

var b = Box { value: 42 }                  // Box<i64>        — inferred
var p = Pair { first: 1, second: "x" }     // Pair<i64, str> — inferred
var b2 = Box<i64> { value: 42 }            // explicit

6. Visibility recap

Struct definition

(none) Only visible to the defining module.

pub Visible to importers of the module.

Per-field

(none) Read/write only from the defining module.

pub Read/write from anywhere the struct is visible.

Edge cases

A pub struct with all-private fields can be returned and held by reference, but not constructed or destructured outside its module.

7. Methods, equality, memory

Method bodies do not live in the struct definition. They live in extend blocks.
No structural equality Two struct values with the same field values are not implicitly equal — equality is whatever Eq says it is, or == is a compile error. Same goes for Hash (no auto-derived) and Ord. See 15-operators.

extern struct is laid out as a C struct, lives on the foreign heap, and has no object header — see 19-ffi.

8. Destructuring

// Record — destructure by name
var Person { name, age } = alice

// In patterns — `..` ignores remaining fields
match alice {
  Person { name, .. } => await print(name),
}

// Tuple — destructure positionally
var Pair(x, y) = p

// Unit — by name, binds nothing
match c {
  Red   => "red",
  Green => "green",
  Blue  => "blue",
}
