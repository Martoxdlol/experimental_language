5. Tuples

Anonymous, structurally-typed groupings of values. Same shape = same type, anywhere.

1. Structural typing

Two tuple types with the same sequence of element types are the same type, regardless of where they appear or what they're aliased to.

Use a tuple when the shape matters; use a struct when the name matters.
var point: (i64, i64) = (3, 4)
var row:   (i64, str, bool) = (1, "Alice", true)

type Point = (i64, i64)
type Z = Point | null
// Z is exactly the same as (i64, i64) | null

Methods extended onto a tuple alias apply to the underlying shape — they're the same type.

2. Positional access

Each position can have a different type, so the index must be statically known.

3. Destructuring & rest

Same rules apply inside match, plus literal patterns: (0, 0), (x, 0), etc.
match point {
  (0, 0)   => "origin",
  (x, 0)   => "x-axis",
  (0, y)   => "y-axis",
  (x, y)   => "elsewhere",
}

4. The 0- and 1-element cases

Zero-element

Not a distinct tuple type. Use null — see 02-types §6.

Single-element

Parentheses around a single expression always denote grouping, not a tuple. There is no one-element tuple type.

If you actually want a "one-element tuple", use a tuple struct or a single-field struct.

6. Tuples in generics

var pairs: List<(i64, str)> = [(1, "a"), (2, "b")]

A tuple shape can be used as a type argument like any other type.

7. Extending tuples

You can extend a tuple type or one of its aliases (they're the same type, so both extensions add methods to the same shape):

type Point = (i64, i64)

extend (i64, i64) {
  function magnitude(self): f64 {
    var x = self.0 as f64
    var y = self.1 as f64
    sqrt(x * x + y * y)
  }
}

// Works regardless of how the value's static type is spelled:
(3, 4).magnitude()
var p: Point = (3, 4)
p.magnitude()
One shape, one method table Because Point and (i64, i64) are the same type, an extension on either applies to both. The orphan rule still applies — see 10-interfaces.
