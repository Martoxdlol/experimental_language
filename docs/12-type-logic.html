12. Type Logic — is, as, and Flow Narrowing

Discriminated unions are first-class. is tests at runtime, as narrows or converts, and the compiler tracks the type of each binding branch-by-branch.

1. is — runtime type check

v is T evaluates to bool. True iff the runtime tag of v indicates it currently inhabits type T.

function describe(v: i64 | str | null): Future<null> async {
  if v is i64 {
    await print("number")
  } else if v is str {
    await print("string")
  } else if v is null {
    await print("nothing")
  }
}

What you can test against

  • Primitive types (i64, f64, bool, char, str).
  • Struct types (regular, unit, tuple).
  • Tuple shapes — v is (i64, str).
  • Type aliases (resolved transparently).
  • null.
No destructuring is doesn't match through patterns — for that, use match (see 07-expressions §3).

2. as — narrowing & conversion

as plays two roles depending on the target type.

Two jobs, same keyword — the target type's relation to the source determines which.

3. Combining is and as

if v is i64 {
  var n = v as i64
  // n: i64 — but `as i64` is redundant here; v is already narrowed to i64
}

You may still write the redundant as for clarity — the compiler does not warn.

4. Flow narrowing

Inside the branches of if, else, match, and short-circuited boolean expressions, the compiler tracks the runtime tag(s) a variable could hold and narrows its type accordingly.

In the then branch, v is exactly i64; in the else, it's the complement.

Narrowing operators

FormEffect
if v is Tthen: v: T · else: v: U \ T
if !(v is T)then: v: U \ T · else: v: T
if v is T { return … }after: v: U \ T
v is T && …RHS sees v: T; if body has cumulative narrowing
v is A || v is Bbody sees v: A | B; incompatible sides → no narrowing
match v { T x => … }arm body: v: T and x: T

Reassignment resets narrowing

var v: i64 | str = 1
if v is i64 {
  v = "x"     // v's narrowed type is now str
  // v: str here, regardless of the surrounding `if v is i64`
}

5. dynamic — the universal union

dynamic is a built-in type that holds any value, of any type, primitive or reference. Conceptually it is the union of every type in the program — T1 | T2 | … | TN — written as a single named type with no pipe enumeration. It exists for the cases where static typing has nothing useful to say: deserialised payloads, plugin boundaries, ad-hoc heterogeneous collections.

dynamic is opaque at compile time. Anything you'd do with it goes through a runtime type check.

Boxing primitives

When a primitive (i32, f64, bool, char, null, …) is widened to dynamic, the runtime wraps it in a heap-allocated box with the standard two-word object header. The box's type pointer identifies the boxed primitive (i32-box, f64-box, …); narrowing back with as reads the header and unwraps the value. See 16-memory §3.

Box identity is implementation-defined Two 42i32 as dynamic expressions may produce the same heap object (small-integer cache) or two distinct boxes. == after narrowing back to the primitive is well-defined; identity comparison on the boxes themselves is not exposed. Don't rely on it.

What dynamic does not implement

The type dynamic itself does not implement ToStr, Clone, Eq, Hash, Ord, or Drop. Calling .to_str() on a dynamic binding is a compile error; channel<dynamic> is rejected because T: Clone can't be satisfied. The pattern is always to narrow first:

function describe(d: dynamic): str {
  if d is ToStr {
    d.to_str()                  // d: ToStr in this branch
  } else {
    "<no string form>"
  }
}

Match on dynamic

A match against a dynamic scrutinee is never exhaustive — every type in the program is in scope. The compiler requires a wildcard arm:

function tag(d: dynamic): str {
  match d {
    i32 n      => "int $n",
    f64 x      => "float $x",
    str s      => "string $s",
    Person p   => "person ${p.name}",
    _          => "other"
  }
}

A dynamic as dynamic cast is a no-op, accepted for generic code that parameterises over the target type.

dynamic is an escape hatch — not the default Static types catch bugs, document intent, and unlock zero-cost dispatch. Reach for dynamic at boundaries (decoded JSON, plugin APIs, debug logging) and narrow back as soon as possible. A function that takes dynamic in and returns dynamic out is almost always wrong.

6. Limits of narrowing

What flow narrowing does not do
  • Applies only to simple bindings — not to field accesses (x.y) or computed expressions. Copy to a local first to narrow.
  • Does not cross function boundaries — a function sees parameters at their declared type.
  • Reset by any reassignment to the variable.
  • Lost when a closure that might mutate the variable is invoked while in the narrowed scope.

7. Examples

function process(input: i64 | str | null): Future<null> async {
  if input is null { return }

  // input: i64 | str

  if input is i64 && input > 0 {
    // input: i64, additionally positive
    await print(("positive: " + (input as str)))
  } else if input is str {
    // input: str
    await print("string: " + input)
  } else {
    // input: i64 (and not positive)
    await print("non-positive: " + (input as str))
  }
}

function unwrap_or<T>(v: T | null, default: T): T {
  if v is null { default } else { v }   // v: T in the else branch
}
