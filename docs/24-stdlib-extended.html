1. The two tiers, revisited

Chapter 18 now defines core: as the compiler/runtime substrate and std: as the official toolchain library. This chapter uses that rule: only language-privileged modules remain in core:; portable but ordinary library APIs move to std:.

core: is the small privileged substrate. std: carries both portable contracts and target-backed implementations.

2. Layering: shape vs runtime

The split is rigid:

core: declares

  • Compiler desugar contracts
  • Runtime-recognized layouts and handles
  • Language-privileged interfaces

std: provides

  • Official portable library APIs
  • Target-backed implementations (files, sockets, clocks)
  • Runtimes and host services

pkg: extends

  • Specific implementations of std:* contracts
  • Alternative runtimes
  • Anything not universal

For example: std:http defines HttpRequest and HttpResponse. A library that ships an HTTP client takes a HttpRequest and returns a HttpResponse. A library that ships an HTTP server consumes HttpRequest. They interoperate without knowing about each other — because the shape is shared.

3. Implementation architecture

The standard library is not one implementation language. Each importable toolchain module is described by a catalog entry with its path, tier, exported symbols, and implementation kind:

Today the compiler's built-in provider is the default catalog. Future sysroots may supply target-specific providers for the same std:* paths — for example POSIX, WASI, embedded, browser, or sandboxed engine profiles — while preserving the documented public shape. A provider may replace a target-backed std:* module, omit it for no-std targets, or add extra target modules gated by the manifest/sysroot. core:* remains the stable, language-privileged substrate that portable packages should rarely depend on directly outside syntax-adjacent APIs. The step-by-step contributor workflow is defined in 29-extending-stdlib.

4. The Request/Response problem

JavaScript's fetch introduced Request and Response late. Before that, every HTTP library shipped its own. The cost compounds:

Standardize the shape; let the implementations compete.

The same logic motivates std:io (Reader/Writer), std:json (the JSON value tree), std:error (the error chain), and std:log (the Logger interface).

5. core:prelude — additions

Chapter 18 originally grouped several core shapes near the prelude. The implemented near-empty-prelude rule keeps named symbols explicit: collections come from core:collections, FFI helpers from core:ffi, and the error chain from std:error. Current placement:

  • List and Map — live in core:collections along with Set.
  • Error, Annotated, with_context — already live in std:error.
  • Bytes — already lives in std:bytes, because it is an ordinary managed library container rather than compiler substrate.

Deque is implemented as std:collections.Deque, an ordinary explicit-import standard-library collection rather than compiler substrate. The import-free surface (what built-in syntax desugars to) contains only language-fundamental shapes (text, iteration, FFI bytes, numeric helpers); see the prelude rule — these are resolved without an import, but naming any of them still requires one.

Why explicit collections List<T> and Map<K, V> are heap-allocated, GC-managed containers. Pulling them out of the prelude makes their use visible at every import site rather than implicit. It also keeps the import-free surface minimal: the prelude after this change holds language-fundamental shapes only (text, iteration, FFI bytes, numeric helpers).

Bytes implements std:io.Writer and std:fmt.FmtSink today as an in-memory sink. set(i, b) mutates one byte and returns false when the index is outside the buffer. insert(i, b) inserts before the byte at index i, accepts i == size() as append, and returns false for negative or out-of-range positions. pop() removes and returns the last byte, or null for an empty buffer. remove_at(i) removes and returns one indexed byte, or null for negative or out-of-range indexes. truncate(len) removes trailing bytes when len is shorter than the current size, clears the buffer for non-positive lengths, and leaves the buffer unchanged when len is larger. resize(len, fill) has the same shrink/clear behavior and appends fill bytes when len is larger than the current size. fill(byte) overwrites every existing byte in place and leaves empty buffers empty. append(other) snapshots the other byte buffer before appending, so b.append(b) doubles the current contents once and then stops. write snapshots its input before appending, so writing a buffer to itself doubles the current contents rather than looping over newly appended bytes. write_str UTF-8 encodes the string and appends those bytes, returning null because an in-memory Bytes sink cannot fail today. Bytes.starts_with and Bytes.ends_with compare raw bytes directly and do not decode UTF-8. Bytes.index_of(byte) and Bytes.last_index_of(byte) return the first or last matching zero-based byte index, or null; Bytes.contains(byte) is the boolean form. Bytes.index_of_bytes(needle) and Bytes.last_index_of_bytes(needle) return the first or last matching raw byte subsequence start index, or null. BytesCursor implements equality and hashing over both the snapshot and current cursor position, plus clone, diagnostic stringification, and std:fmt.Debug. The Reader.read(buf) implementation appends up to the current buf.size() bytes, matching the existing std:io.Reader contract; read_to_end(buf) appends all remaining bytes. Bytes.decode_utf8() validates strict UTF-8 and rejects invalid leading bytes, malformed continuations, truncation, overlong sequences, surrogate code points, and scalar values above U+10FFFF. Utf8Error implements std:error.Error, equality, clone, hash, diagnostic stringification, and std:fmt.Debug; the type exists now so the decoder has a stable error shape. Future slices will add pinned Buffer views. The implemented ToStr rendering is a compact diagnostic form like bytes[65,66], not UTF-8 decoding.

6. core:collections — List · Map · Set · Entry

Explicit-import module within the core: tier. Holds the runtime-recognized, GC-managed collection shapes that the compiler lowers, constructs, traces, or reserves for collection syntax.

import { List, Map, Set, Entry } from "core:collections"

var xs: List<i64>     = [1, 2, 3]
var m:  Map<str, i64> = { "x": 1 }
var s = Set<str>()
s.insert("a")
Literal syntax still respects the near-empty prelude The implemented literal forms [...] and { k: v, ... } are language-level syntax (chapters 1 & 18). They construct the corresponding container type — but the name List, Map, or Set must still be imported to write type annotations, call static constructors, or use named methods. Set also remains in this substrate because the compiler recognizes its construction/tracing shape and reserves it for future set literals. Set literals remain planned.

7. std:io — Reader · Writer · AsyncReader · AsyncWriter · Seeker

The single most load-bearing addition. Reader, Writer, and Seeker are ordinary value-returning contracts for non-waiting in-memory sources and adapters. They are not target-stream protocols, and wait-capable providers such as files, sockets, stdin/stdout/stderr, and child-process pipes must not implement them for operations that may wait. Target-backed byte streams instead expose async methods and/or implement AsyncReader and AsyncWriter, the Otter Fusion async counterparts to those contracts. Target-backed I/O sources are documented only through explicit future-returning operations.

pub interface Reader {
  // Reads up to buf.size() bytes. Returns bytes-read, or 0 on EOF, or IoError.
  function read(self, buf: Bytes): i64 | IoError

  // Convenience: read until EOF, append to buf. Implemented by each Reader.
  function read_to_end(self, buf: Bytes): i64 | IoError
}

pub interface Writer {
  function write(self, buf: Bytes): i64 | IoError
  function write_all(self, buf: Bytes): null | IoError
  function flush(self): null | IoError
}

pub interface AsyncReader {
  function read_async(self, buf: Bytes): Future<i64 | IoError>
}

pub interface AsyncWriter {
  function write_async(self, buf: Bytes): Future<i64 | IoError>
}

pub interface Seeker {
  function seek(self, pos: SeekFrom): i64 | IoError
}

pub union SeekFrom = Start { offset: u64 }
                   | Current { offset: i64 }
                   | End { offset: i64 }

pub struct IoError {
  pub kind: IoErrorKind,
  pub message: str,
}

pub union IoErrorKind = NotFound | PermissionDenied | ConnectionRefused
                      | IoTimedOut | UnexpectedEof | Interrupted | OtherIo

The implemented catalog exports the contracts above, IoError, IoErrorKind, the seek-position variants, async print, and println, plus async stderr counterparts eprint and eprintln. It also exports concrete stdin(), stdout(), and stderr() handle constructors whose target-backed methods are the awaitable surfaces. IoTimedOut and OtherIo are deliberately named with an IO prefix for clarity at call sites; bundled toolchain source now uses hidden module-local owners under the private __builtins__ root, so future modules can still use ordinary local names without colliding across std:* packages.

std:io ordinary and async contracts are explicit. Top-level helpers print, println, eprint, and eprintln return Future<null> and must be awaited. Concrete stdin(), stdout(), and stderr() handle methods such as read, read_to_end, write, write_all, and flush also return Futures; their *_async aliases remain available for explicit async-byte-stream code. Generic in-memory Reader.read, Reader.read_to_end, Writer.write, Writer.write_all, Writer.flush, and Seeker.seek return ordinary values, not Futures, because they are not target-backed I/O. Stdin, Stdout, and Stderr deliberately do not implement these ordinary in-memory contracts. In-memory BytesCursor readers and Bytes writers are ordinary in-memory contract implementors unless they explicitly implement AsyncReader/AsyncWriter; those protocols are not inferred from the ordinary contracts. Buffered adapters over in-memory streams forward those same ordinary contracts; BufReader.read, BufReader.read_to_end, BufReader.read_line, BufReader.lines, BufWriter.write, BufWriter.write_all, and BufWriter.flush are also ordinary value-returning boundaries. Concrete stdio handles expose helper-backed async methods that wake through the reactor, and generic async byte-stream code can use AsyncReader/AsyncWriter. There is no generic async seeker protocol today.

SeekFrom and IoErrorKind are union aliases. They provide direct equals(...) helpers plus Eq.eq, overloaded ==, Clone, Hash, ToStr, and Debug methods. IoError is struct-shaped and implements Error, Eq, Clone, Hash, and Debug.

8. std:fmt — Display & Debug

Chapter 18 notes that there is no formatting machinery. The roadmap adds the minimum needed to prevent every library inventing its own stringification. The existing ToStr interface (§15) becomes the Display output path.

// User-facing string form. Display is also a ToStr implementation.
pub interface Display: ToStr {
  function display(self): str
  function to_str(self): str
}

// Developer-facing form. Distinct from Display so logging / debug output
// can show types differently from how they appear to end users.
pub interface Debug {
  function debug(self): str
}

// Sink for incremental writes — usable with anything implementing Writer
// or with a Bytes buffer.
pub interface FmtSink {
  function write_str(self, s: str): null | FmtError
}

pub struct FmtError { pub message: str }

The contract surface is implemented in the Otter-authored std:fmt module. std:bytes.Bytes implements FmtSink as the standard in-memory UTF-8 formatting sink. FmtError implements std:error.Error, equality, clone, hash, and diagnostic debug rendering so sink failures can be compared, copied, stored in hash-based structures, and passed through generic error code. The pure stdlib value types std:bytes.Bytes, std:bytes.Utf8Error, std:time.Duration, std:time.Instant, std:time.SystemTime, std:fs.Path, std:json.Json, std:net/types identifier values, and struct-shaped std:http values implement Debug. Collections implement diagnostic rendering when their contents are renderable: List<T: Debug>, Set<T: Eq + Debug>, and Map<K: Eq + Hash + ToStr, V: Debug>. Primitive scalar and str values implement Debug through compiler/runtime intrinsics, including primitive-to-std:fmt.Debug interface objects and generic T: Debug monomorphization. Numeric and boolean values use their ordinary string form; char and str render quoted with diagnostic escapes.

Format strings are still out No format! macro is added. String interpolation (chapter 1) is the only formatting sugar. Display / Debug exist purely so libraries can agree on how to stringify a value when interpolation is not enough.

9. std:error — error interface

The Error interface, the Annotated wrapper, and with_context are implemented in the dedicated std:error module. They are imported explicitly like the rest of the near-empty-prelude standard library surface.

pub interface Error: ToStr {
  function message(self): str
  function cause(self): Error | null
}

pub struct Annotated {
  pub note:   str,
  pub source: Error,
}

extend Annotated: Error {
  function message(self): str          { self.note }
  function cause(self):   Error | null { self.source }
  function to_str(self):  str          { self.note + ": " + self.source.to_str() }
}

extend Annotated: Debug {
  function debug(self):   str          { "Annotated { note: \"" + self.note + "\", source: " + self.source.to_str() + " }" }
}

pub function with_context<T, E: Error>(
  value: T | E,
  note: str,
): T | Annotated

Annotated implements std:fmt.Debug for diagnostics, but it does not implement generic clone, equality, or hash. Its source field is only constrained to Error, and the Error interface deliberately does not promise those value semantics.

Conventions (recap from chapter 13)
  • Libraries define their own error structs, then extend them with Error. They still appear in unions (T | MyError); the interface just lets them flow into generic error-handling code.
  • ? (chapter 13) continues to work on unions; this module adds nothing to its rules.
  • Logging and tracing libraries accept any Error without knowing the concrete type, and call to_str() to render.
  • ToStr (chapter 15) remains the interpolation path. Libraries that need separate user-facing or developer-facing rendering can additionally accept std:fmt.Display or std:fmt.Debug.

Duration is portable Otter-authored value API. Named timezone conversion returns TimeError until provider-backed timezone databases exist. DateTime.now_utc(), DateTime.now_local(), and DateTime.from_system_time_local(t) are awaitable and implemented over private target-backed clock and local-offset futures. Local conversion captures the provider's UTC offset for that timestamp and returns a fixed-offset DateTime; the local-offset provider lookup is private runtime machinery behind the future and does not resolve a named timezone. DateTime.with_timezone(tz) rebuilds the value with the same local date/time fields and a cloned replacement timezone.

TimeError implements std:error.Error, equality, clone, hash, and debug rendering. sleep(Duration) returns Future<null> and suspends through the runtime timer/reactor path without parking the caller's executor worker. Non-positive durations produce an immediately settling timer future; positive sub-millisecond durations round up to one millisecond. Editor namespace completion keeps the duration-based Time.sleep surface distinct from millisecond-based Async.sleep, and both are awaitable timer futures. Timezone databases, named-zone conversion, and leap-second policy remain planned follow-up work.

TcpStream and TcpListener are implemented as mixed stdlib handles over provider TCP sockets. They are deterministic @RefCounted values backed by opaque runtime handles; cloning preserves the shared handle, close() releases it explicitly, and dropping the last Otter value releases the runtime registry entry. TcpStream byte I/O methods return futures rather than implementing the ordinary non-waiting Reader/Writer contracts, while TcpListener.accept() returns a future that resolves to both the accepted stream and peer SocketAddr. Stream metadata/control and listener bind, metadata, error-readback, nonblocking, TTL, and close members also return futures under the corrected no-public-blocking contract. The implemented TCP option surface includes TCP_NODELAY readback/set, IP TTL get/set operations, and pending socket-error readback through take_error() for streams. TCP streams and listeners also expose provider-backed set_nonblocking toggles for code that deliberately manages provider readiness outside the Otter Fusion executor; switching the flag does not replace the documented future-returning TCP stream and listener surfaces. TcpStream additionally exposes read/write timeout get/set operations using std:time.Duration; passing null clears the provider timeout, while negative or unsupported timeout values surface as IoError.

AsyncTcpStream is an explicit async network adapter and implements std:io.AsyncReader/std:io.AsyncWriter. It is a normal stdlib value that wraps a provider TCP stream handle without changing the underlying handle identity. connect(addr), connect_timeout(addr, timeout), read_async(buf), write_async(buf), and peek_async(buf) return Futures and wake through the runtime reactor path; their provider waits run off the executor worker so a poll does not park the task scheduler. Helper-thread creation is bracketed as a runtime native-state boundary; the helper path brackets only the provider wait with GC native-state transitions; encoded Otter result values are created after that wait has ended. Cancellation removes the future's reactor registration, drops the eventual result if the helper completes later, and releases any TCP stream handle created by a late cancelled connect, connect_timeout, or accept. Timed-out helper-backed reads may consume the provider bytes that satisfied the late read; the runtime discards that stale result and keeps the stream usable for subsequent operations. The timed variants use the provider's finite TCP connect operation and report invalid negative durations as ordinary IoError values. Other async TCP operation deadlines are expressed today with std:async.timeout(stream.read_async(buf), ms), timeout(stream.write_async(buf), ms), or timeout(stream.peek_async(buf), ms); dedicated per-operation timeout method families such as read_timeout_async, write_timeout_async, or peek_timeout_async are not part of the current API. from_stream(stream) adapts an existing stream explicitly, and into_stream() returns the plain stream handle; both conversion helpers return ordinary values, not Futures. Stream metadata and handle control methods such as peer_addr, local_addr, and close also return Futures through the same public stream-control contract. Async TCP has GC-stress coverage for managed state kept live across helper-backed write/read awaits.

AsyncTcpListener is the matching explicit TCP accept adapter. UdpSocket is implemented as a mixed stdlib handle over provider UDP sockets. It is also a deterministic @RefCounted runtime handle. Its bind/connect/datagram/metadata/control/option/multicast/close operations return Futures: send_to sends one datagram from a Bytes buffer, and recv_from appends one received datagram into the caller-provided buffer and returns the byte count plus source SocketAddr. peek_from uses the same caller-owned buffer convention and returns the same source address without consuming the datagram. The implemented UDP option surface includes IP TTL get/set operations and provider UDP broadcast, IPv4/IPv6 multicast-loop, and IPv4 multicast-TTL readback/set operations plus pending socket-error readback through take_error(). AsyncUdpSocket is the explicit UDP datagram adapter. It wraps a provider UDP socket while sharing the same helper-backed datagram future path as UdpSocket. bind(addr) returns Future<AsyncUdpSocket | IoError>. Connected send_async, recv_async, and peek_async, plus address-aware send_to_async, recv_from_async, and peek_from_async, return Futures and wake through the runtime reactor path; provider waits run off the executor worker and own their GC native-state bracket. Helper-thread creation is bracketed as a runtime native-state boundary. Cancellation removes the reactor registration, and late helper results are discarded. A timed-out UDP receive may still consume the provider datagram that satisfied the cancelled helper; the cleanup contract is that the stale result is dropped, the waiter is gone, and the socket remains usable for later datagrams.
