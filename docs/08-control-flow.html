8. Control Flow

Three loops — for, while, loop — plus break and continue. Bare-keyword headers; parens only when a struct literal would be ambiguous.

The three loop shapes at a glance

Pick the loop by its termination story: collection, condition, or break-out-with-a-value.

1. for loop

Iterates over any value implementing Iterator<T> (see 18-stdlib):

for n in numbers {
  print(n as str)
}

for (k, v) in map_entries {        // Iterator<(K, V)>
  print(k + ": " + (v as str))
}

for Entry { key, value } in user_ages {
  print(key + " -> " + (value as str))
}

The pattern must be irrefutable (always matches the yielded type).

Direct iteration shortcuts Collections that aren't iterators expose factories: list.iter(), map.entries(), map.keys(), map.values(). As a convenience, lists, maps, and strings are accepted directly:
  • for x in list — yields T
  • for entry in map — yields Entry<K, V>
  • for ch in s — yields char

2. while loop

while i < 10 {
  print(i as str)
  i = i + 1
}

The condition must be bool. Evaluated before each iteration.

3. loop — infinite loop

loop {
  if done { break }
  do_work()
}

Runs forever until break. Unlike while true, the compiler knows loop is irrefutably infinite, so it accepts code that depends on break for control-flow type inference:

var result = loop {
  if found { break value }
}
// `result` has the type of `value`

4. break & continue

continue returns to the head; break exits — only loop can break with a value.
for x in xs {
  if x < 0 { break }
  process(x)
}

var first_match = loop {
  var item = next_item()
  if item is null { break null }
  if matches(item) { break item }
}

for n in numbers {
  if n < 0 { continue }
  print(n as str)
}

5. Loop expression types

LoopType when used as an expression
for ... in ...null
while condnull
loop (no value-break)never — the loop never returns; surrounding code is unreachable
loop (with break <expr>)Unified type of every break expression
The "never" type In type unification, never is absorbed: var x = if cond { 5 } else { loop {} } ⇒ x: i64. The loop {} branch can never produce a value, so it doesn't contribute to the union.

6. Nested loops

break and continue always act on the innermost enclosing loop. There are no labeled loops in this version of the spec.

Multi-level exit? Use a function and return: 
function search(): Item | null {
  for row in rows {
    for cell in row {
      if matches(cell) { return cell }
    }
  }
  null
}
Labeled loops may be added later but aren't required for completeness.

7. Iterator protocol — quick reference

interface Iterator<T> {
  function next(self): Item<T> | Done
}

struct Item<T> { value: T }
struct Done;
The loop body sees T; iteration ends when next() returns Done.

8. Examples

function sum(xs: List<i64>): i64 {
  var total: i64 = 0
  for x in xs {
    total = total + x
  }
  total
}

function find_first<T>(xs: List<T>, pred: (T) => bool): T | null {
  for x in xs {
    if pred(x) {
      return x
    }
  }
  null
}

function countdown(from: i64) {
  var n = from
  while n > 0 {
    print(n as str)
    n = n - 1
  }
  print("liftoff")
}

function poll_until_ready<T>(ch: Receiver<T>): T {
  loop {
    var msg = ch.try_recv()
    if msg is null {
      sleep(10)
      continue
    }
    break msg as T
  }
}
