1. Naming — @UpperCamelCase

Macro names use UpperCamelCase, like struct and interface names. This visually separates a macro invocation from a regular function call (snake_case). The compiler rejects @lowercase_name.

2. Three invocation forms

Same proc-macro signature handles all three — the position determines the input shape.

Arguments & stacking

@Route("/api/users", method = "GET", auth = true)
@JsonSerializable        // bare — parens optional when no args
Stacked decorators apply bottom-up 
@Derive(Clone)            // applied second — sees the @JsonSerializable output
@JsonSerializable         // applied first — sees the raw struct
pub struct Config { ... }
Equivalent to Derive(Clone, JsonSerializable(raw_struct)).

3. Macro definition

import { MacroContext, ASTNode } from "core:compiler"

@ProcMacro
pub function JsonSerializable(ctx: MacroContext, input: ASTNode): ASTNode {
  // inspect input, build a new AST, return it
}
  • The function name (UpperCamelCase) is the macro's invocation name.
  • Signature is always (MacroContext, ASTNode) => ASTNode. Bundle multiple inputs into an args node.
  • Must be pub for cross-module use; @ProcMacro functions follow the same pub mod chain.
  • Cannot import any std:* module — the compiler refuses to load OS-dependent macro plugins (see §6).

4. Compilation phases

Macro expansion is phase 2 of seven — before type checking, before module resolution.

A macro's output may contain further @ invocations — the compiler re-runs phase 2 until fixed.

5. Hygiene

Hygienic by default Identifiers a macro introduces live in a fresh syntax context. A var temp = ... emitted by a macro cannot collide with a caller's temp, even with identical spelling. 
// Hygienic temp — won't collide with caller's `temp`
var temp = ctx.fresh_ident("temp")

// Unhygienic — leaked into the caller's scope (e.g. @Derive synthesizing methods)
var name = ctx.unhygienic("from_json")

Use ctx.unhygienic(...) sparingly — most macros should keep their internal bindings hygienic.

6. Sandbox

Sandbox is enforced by the plugin runtime — not a convention.

7. Errors & diagnostics

@ProcMacro
pub function Route(ctx: MacroContext, input: ASTNode): ASTNode {
  var path = ctx.arg_string("path")
  if path is null {
    ctx.error(ctx.invocation_span, "@Route requires a 'path' argument")
    return ASTNode.error_marker()
  }
  // ... build the transformed AST
}
ASTNode.error_marker() Sentinel that tells the compiler "I've already reported the problem; suppress downstream checks on this subtree". Compilation continues — the user sees as many errors as possible per build. ctx.error does not abort the macro; it accumulates.

8. MacroContext API — sketch

pub interface MacroContext {
  // span of the @MacroName itself
  function invocation_span(self): Span

  // arguments to the @MacroName(...) invocation
  function args(self): List<ASTNode>            // positional, in order
  function kwargs(self): Map<str, ASTNode>      // keyword args

  // argument coercion helpers (return null if missing or wrong shape)
  function arg_string(self, name: str): str | null
  function arg_int(self, name: str):    i64 | null
  function arg_bool(self, name: str):   bool | null
  function arg_ident(self, name: str):  str | null

  // diagnostics
  function error(self, span: Span, message: str)
  function warn(self,  span: Span, message: str)
  function note(self,  span: Span, message: str)

  // hygiene escape
  function unhygienic(self, name: str): ASTNode

  // identifier minting (hygienic temp names)
  function fresh_ident(self, hint: str): ASTNode
}

9. ASTNode — deferred

Exact schema in a future spec The full ASTNode schema is deferred. This version commits to:
  • It is a discriminated union with one variant per syntactic category.
  • Every node carries a Span for diagnostics.
  • Nodes are immutable; "modifying" produces a new node.
  • Re-parse from source via core:compiler helpers — parse_item, parse_expr, parse_block — letting macros generate code by string concatenation when convenient.

10. Recursion & depth limit

A macro's output may contain further @ invocations. The compiler re-expands them until none remain. Default depth limit: 128 levels.

[macros]
recursion_limit = 256

A macro that recursively emits itself with no termination hits the limit and is rejected; the error includes the invocation chain.

11. Built-in @Derive

@Derive(Eq, Hash, Clone, Ord)
pub struct Person {
  pub name: str,
  pub age:  i32,
}
DerivableRequiresSynthesizes
@Derive(Eq)every field Eqextend T: Eq — field-by-field equality
@Derive(Ord)every field Ord; implies Eqextend T: Ord — lexicographic by declaration order
@Derive(Hash)every field Hashextend T: Hash — combined hash of all fields
@Derive(Clone)every field Cloneextend T: Clone — deep copy of every field
User-defined @Derive(MyTrait) Resolves to a macro named Derive_MyTrait (compiler concatenates the dispatch name). Define it like any other @ProcMacro.

12. No declarative macros

One mental model — procedural only No macro_rules!-style declarative macros. Rationale: one mental model, full generality, no fragment-specifier mini-grammar to learn. Trade-off: more boilerplate for simple template substitutions — for those, write a small @ProcMacro that calls parse_expr/parse_item over a formatted string.

Summary

  • @UpperCamelCase invocation. Three positions: decorator on items, expression, block.
  • Multiple decorators apply bottom-up.
  • Macros are pub function Name(ctx: MacroContext, input: ASTNode): ASTNode marked @ProcMacro.
  • Macros run in phase 2 — before type checking and import resolution.
  • Hygienic by default; ctx.unhygienic(...) to deliberately leak a name to the caller.
  • Sandboxed: no I/O, no threads, no type info, no global state. Pure AST-to-AST.
  • Errors via ctx.error(span, msg); return ASTNode.error_marker() to suppress downstream noise.
  • Recursion limit 128, configurable.
  • @Derive(...) is the only blessed macro in core:prelude — Eq, Ord, Hash, Clone.
  • No declarative macro_rules!-style form.
