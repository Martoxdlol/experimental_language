16. Memory Model

Refcount + cycle collector hybrid GC. Two disjoint heaps — managed and foreign. Drop is best-effort; refcount traffic is mostly elided by the compiler.

1. The two heaps

Distinct address ranges. A runtime address-range check identifies managed vs foreign pointers; foreign pointers are ignored by the GC entirely.

2. Value vs reference semantics

Value (primitives)

Stored inline (stack, struct fields, registers). Assignment copies the value.

i8..i64, u8..u64, f32, f64, bool, char, null, usize, isize.

Reference (the rest)

The variable holds a pointer to a managed-heap object. Assignment copies the pointer (and increments the refcount). Mutation through one binding is visible through every other binding holding the same pointer.

str, List<T>, Map<K, V>, structs, interface objects, function values that capture state, boxed tuples.

To get an independent copy, call .clone() — see 15-operators §Clone.

3. Object layout

Every managed-heap object has the same header layout. The pointer held by a variable points to the start of the object fields; the header lives at negative offsets — so normal field access does not need to skip the header.

Exact sizes are implementation-defined; treat the layout as conceptual. extern struct types have no GC header.

4. Refcount semantics

EventRC change
Assignment to new binding · capture into long-lived closure · push into collection · send over channelincrement
Scope exit · reassignment · replacement in collectiondecrement
Object reachable from multiple threadsatomic ops (conservative)

When refcount hits 0:

  1. Drop.drop(self) if Self implements Drop.
  2. Each strong-referencing field has its refcount decremented (recursively).
  3. The object's memory is returned to the allocator.
Compiler elides most inc/dec Last-use analysis turns inc/dec pairs into pointer moves. If x is passed to a function and not used afterward, the compiler hands off the reference. If x is returned, the inc/dec at the return site cancels with the call-site receive. This makes refcount overhead near-zero for straight-line code, and powers zero-copy channel sends when RC=1 — see 20-concurrency.

5. Cycles & the cycle collector

Pure refcounting cannot reclaim cycles. The runtime includes a cycle collector that runs periodically.

Roots: thread stacks, module-level vars, captured environments of live closures, pinned objects.
Drop inside cycle collection: safe patterns
  • Touch only primitive fields of self.
  • Release foreign resources (file descriptors, malloc'd buffers).
  • Log or count (provided logging is itself drop-safe).
Unsafe patterns
  • Call methods on referenced managed objects (they may already be dropped).
  • Resurrect self by storing it into a long-lived location.
  • Panic — see 14-panics §4.

6. Drop determinism

ScenarioGuarantee
Linear (non-cyclic) chain, scope exitDeterministic — called at scope exit
CycleEventually, unspecified order, when collector runs
Program exitBest-effort pass, no guarantee
Panicked threadStack roots dropped; objects only reachable from that thread may leak until cycle-collected
Don't rely on Drop for correctness Programs that need deterministic finalization (file flushing, etc.) should release resources explicitly before scope exit, not depend on Drop.

7. Inline / stack allocation

The compiler may "inline" small heap objects onto the stack when their lifetime is provably bounded by a single frame. Invisible at the language level — observable semantics are always as if the object lived on the managed heap.

Tuples and small structs are the most common candidates. The compiler proves the value does not escape (returned, captured into an escaping closure, sent over a channel, stored in a collection) and replaces the heap allocation with a stack slot.

8. Type identification

The type id field is a compile-time-assigned integer identifying the concrete type. This is what is/as consult at runtime.

Type IDs are stable within a single compilation. Across separate compilations or dylib boundaries, a runtime registry maps type identity by structure (nominal types by fully-qualified module-and-name; tuple shapes by structural hash).

Interface dispatch is not based on type id alone — it uses a vtable pointer that is part of the interface-object representation (a fat pointer). See 11-generics.

9. Allocation failure

Managed allocation is infallible (panics on OOM) There is no fallible alloc for managed code. Foreign allocation via malloc is fallible — returns null to the user. See 19-ffi.

10. Concurrency interactions

  • The refcount field is updated atomically when the runtime determines the object is reachable from more than one thread.
  • For thread-local objects, refcount updates are non-atomic (a single-thread optimization).
  • Cross-thread reads/writes of struct fields are not synchronized — use Shared<T> or channels.
Memory safety vs race-freedom The language guarantees memory safety (no use-after-free) for managed pointers across threads. It does not guarantee race-freedom on object contents — that's on you. See 20-concurrency.

11. Pinning

Pinning a managed object adds a strong root that prevents the cycle collector from moving (if a moving collector is in use) or reclaiming the object until the pin is released.

Pinning is refcounted per object: nested pins on the same value compose correctly. Pinning a value that already lives on the foreign heap is a no-op.

User-facing entry points:

  • &expr at extern call sites — auto-pin for the call's duration.
  • with_pin(value) { ptr => ... } — scoped pin across a closure body.
  • Pin.acquire(value) — long-lived pin returning a PinHandle<T>, released explicitly or on Drop.

There is no direct pin/unpin user API. See 19-ffi §pinning.

12. Summary

  • Refcount + cycle collector hybrid GC.
  • Managed objects share a uniform header: [gc header | type id | fields], pointer at the field boundary.
  • Primitives by value; references inc/dec a refcount.
  • Compiler elides redundant inc/dec via last-use analysis (used by channels for zero-copy moves).
  • Drop is best-effort, not guaranteed; don't depend on it for correctness.
  • Two heaps; the GC ignores foreign pointers.
