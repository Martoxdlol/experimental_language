10. Interfaces and Extensions

Interfaces define behavior contracts. Methods and impls live in extend blocks — struct declarations are data only.

Data and behavior, separated

Three roles, three places. struct never carries method bodies in this language.

1. Interface declaration

pub interface Named {
  function name(self): str
}

pub interface Shape {
  function area(self): f64
  function perimeter(self): f64
}

// With default implementations
pub interface Named2 {
  function name(self): str

  function greet(self): str {
    "Hello, " + self.name()
  }
}

// Static method (no self) + Self type — see §10
pub interface Default {
  function default(): Self
}

extend i32: Default {
  function default(): i32 { 0 }
}

var zero = i32.default()

// Self in an instance method
pub interface Clone {
  function clone(self): Self
}

Default methods

A method with a body is a default: an implementer that omits it inherits the default, and one that provides it overrides. The default body is checked in the implementer's context, so Self and every required method resolve against the implementing type. A default that calls a required method the type never provides is an ordinary "no such method" error. 

// Generic interface — the parameter `T` flows into the default body.
pub interface Bounded<T> {
  function value(self): T
  function or_value(self, fallback: T): T {   // default
    self.value()
  }
}

extend Cell: Bounded<i64> {                    // `T` → `i64` in the copied default
  function value(self): i64 { self.v }
}
Where defaults come from Three forms are supported, all equivalent at the use site:
  • Same module — the interface is declared alongside the extend.
  • Generic interface — the interface's type parameters are substituted with the extend's arguments (Bounded<T> implemented as Bounded<i64> ⇒ T becomes i64) throughout the inherited signature and body.
  • Cross-module — a pub interface imported from another module supplies its defaults just as a local one would.

2. Interface composition

pub interface Printable: Named {
  function to_string(self): str
}

pub interface Renderable: Printable + Sized {
  function render(self): str
}

Implementing a sub-interface requires the type to also implement every super-interface.

3. self parameter

self is typed as Self and is implicitly annotated — you never write its type.
No &self / &mut self For managed reference types, mutation is always allowed. Copying requires an explicit .clone() (see 15-operators).

4. extend — adding methods & impls

extend Person {
  function become_older(self) {
    self.age = self.age + 1
  }
  function is_adult(self): bool {
    self.age >= 18
  }
}

extend Person: Named {
  function name(self): str { self.name }
}

// Combined — an impl block can add extra methods
extend Person: Printable {
  function to_string(self): str { ... }
  function debug_dump(self): str { ... }   // not part of Printable
}

Multiple extend blocks for the same type are allowed and combine additively. Two definitions of the same method name in the visible set is an error.

5. Generic extensions

struct Wrapper<T> {
  pub value: T,
}

// Applies to every Wrapper<T>
extend<T> Wrapper<T> {
  function get(self): T { self.value }
}

// Specialization — only for Wrapper<i32>
extend Wrapper<i32> {
  function double(self): i32 { self.value * 2 }
}

// Generic interface impl
extend<T> Wrapper<T>: Named {
  function name(self): str { "Wrapper" }
}

// Constrained generic impl
extend<T: Clone> Wrapper<T>: Clone {
  function clone(self): Wrapper<T> {
    Wrapper { value: self.value.clone() }
  }
}

6. Primitives, unions & aliases

extend i32 {
  function is_even(self): bool { self % 2 == 0 }
}

// Unions and aliases too
struct Red;
struct Blue;
type Theme = Red | Blue

extend Theme {
  function is_cool(self): bool { self is Blue }
}
Normalization carries through extend (Red | Blue), extend (Blue | Red), and extend Theme all refer to the same type and stack methods together. Tuple alias methods are added to the shape: type Point = (i64, i64) and (i64, i64) share their method set.

7. Orphan rule & coherence

To prevent ambiguous impls across modules, an extend T: I block must originate in either T's defining module or I's defining module.

"Local" = the impl block sits in the same module as the type or as the interface.

8. Interface objects — dynamic dispatch

An interface type used as a value type (parameter, field, variable) is an interface object — a fat pointer to a heap value plus a vtable pointer. Calls through an interface object dispatch dynamically.

Same code shape; trade-off is monomorphization cost vs vtable indirection. See 11-generics for the full story.
Object safety: interfaces that mention Self If an interface method mentions Self outside the self parameter (e.g. Clone.clone(self): Self), it is not object-safe — you can't use it as an interface object value. Use generics instead: 
function bad(x: Clone): Clone { x.clone() }       // ERROR
function ok<T: Clone>(x: T): T { x.clone() }      // OK

9. Method resolution

At a call site value.method(args):

  1. Inherent methods on the value's concrete type (from extend T { ... } blocks).
  2. Methods supplied by any interface implementation visible at the call site.

Ambiguity (two different impls both providing the same method) is a compile error. Disambiguate by calling through the interface explicitly:

Printable.to_string(person)

10. Static methods

A method declared in an extend or interface block without a self parameter is a static method (an associated function). There is no static keyword — the absence of self is the whole signal. It belongs to the type rather than to a value, and is called with the type on the left of the dot — the . analogue of Rust's Type::method(args).

struct Point { x: i64, y: i64 }

extend Point {
  function origin(): Point { Point { x: 0, y: 0 } }   // no self → static
  function at(x: i64, y: i64): Point { Point { x: x, y: y } }
  function manhattan(self): i64 { self.x + self.y }   // has self → instance
}

var o = Point.origin()        // static call on the type
var p = Point.at(3, 4)
var m = p.manhattan()         // instance call on a value
No keyword — self is the distinction. A function with a leading self parameter is an instance method; one without is static. A static method may not be called on a value, and an instance method may not be called on the type — both are compile errors.

Static methods through a generic bound

An interface may declare static methods (often returning Self). Generic code calls them on the type parameter, and the compiler monomorphizes the call to the concrete implementation — exactly like an instance interface method, but with no receiver:

interface Default {
  function default(): Self          // no self → a static requirement
}

struct Config { level: i64 }
extend Config: Default {
  function default(): Config { Config { level: 1 } }
}

function build<T: Default>(): T {
  T.default()          // resolves to the concrete type's impl at each instantiation
}

var c = build<Config>()   // c == Config { level: 1 }
Constructor shorthand. For any type T exposing a new static method, T(args) is sugar for T.new(args) in value position (see 09-functions §10). Tuple structs are not rewritten — Pair(1, 2) is always direct construction.
